# Anda 记忆产品设计：从“集成了大脑”到“越用越省心”

状态：设计提案，未实施。依据当前仓库代码及 Brain/MIB 集成文档，未做真实用户访谈或效果实验。本文新增入口、命令、文案、界面与指标均为拟议设计；当前已有能力单独注明。下文时长与指标是设计目标，不是已测结果。

实施拆解：[技术实施方案](memory-implementation-plan.md)，包含接口合同、数据迁移、工作包依赖和验收矩阵。

## 1. 产品决策

普通用户只需要知道一句话：**告诉 Anda 一次，之后做事少解释一些；记错了，可以查清楚、改过来。**

默认使用普通长期记忆，沿用现有模型配置。用户不必选择 Brain、配置运行时、编译 learning，也不必运行 MIB。“零门槛”指无需额外理解和配置记忆系统，不意味着不需要可用模型、不产生模型费用，或所有事实都能被正确保留。

将现有能力分成三个用户层次：

| 面向谁 | 用户入口 | 用户想完成的事 | 默认策略 |
| --- | --- | --- | --- |
| 日常使用者 | **记忆** | 记住偏好、接续项目、修正旧信息 | 跟随正常聊天可用 |
| 有持续关注需求的使用者 | 记忆 → **需要确认** | 回答一个具体问题，让后续工作继续 | 有实际事项才出现；配置引导按需展示 |
| 开发者、评测者、部署者 | 设置 → 高级 → **记忆实验室** | 验证收益、接入业务学习 | 独立入口，显式预算与授权 |

Brain 保留为引擎名称；MIB 保留为高级协议名称。Formation、Recall、CWT、cohort 等词不进入日常使用主路径。知识图谱保留在“探索关系”里，默认首页展示用户可读的信息和下一步行动。

**首先交付可验证的记忆闭环，再做自动学习。** 用户修正了一条偏好、系统保存了一次对话、一次对比实验提升了成绩，是三种不同的产品事实。

衡量这个产品最重要的问题是：**一周后回来，用户能否少说背景、继续完成事情，而且出错时知道怎么纠正？** “创建了多少记忆”只能用于排障，不能作为核心价值。

### 已有基础与需要新建的产品层

| 当前已有 | 需要补齐 |
| --- | --- |
| 普通聊天后台形成记忆、按需召回、维护 | 用户看得懂的状态，以及与原消息关联的结果 |
| 图谱浏览、只读查询 | 有来源、有范围、便于核对的记忆视图 |
| 原生持久待办、隔离身份、回答收据 | 按需 setup、事项创建、无需技术参数的回答体验 |
| 隔离 MIB 适配服务 | 实验 runner、预算、评分和报告 |
| 可配置的 learning 绑定 | 经过验证的业务模板、准备度检查、授权与回退流程 |

这一层主要是宿主编排、用户视图和默认路径。沿用现有 Brain 原生能力；源端缺少必要查询或写入合同的部分明确列为依赖，不能用前端假状态填补。

## 2. 当前体验为何难用

以下是代码走查结论，不是已观察到的用户研究结果。

| 当前入口或行为 | 用户可能形成的误解 | 产品调整 |
| --- | --- | --- |
| 集成文档从 runtime YAML、身份和启动约束开始 | “不开这些就没有记忆” | 第一屏先给无额外配置的普通记忆用法 |
| `/brain` 当前默认请求 attention inbox | “未配置/无权限，所以记忆坏了” | 默认打开普通记忆概览，待办单独检查 |
| 浏览器 Brain 首屏是图谱、概念数、关系数 | “很复杂，但和我的工作有什么关系” | 默认给偏好、项目背景、最近更正、需要确认 |
| 普通对话后台提交 Formation | “助手说记住了，已经永久保存” | 确认收到、正在整理、整理结果分开显示 |
| 查询 Formation 需要知道 conversation ID | “我怎么知道刚才那句话存好了没有” | 在原消息旁关联状态，用户不输入 ID |
| 待办回复在 TUI 要求 ID、event_key | “回答一个问题也像调 API” | 选事项、填答案；幂等键和重试由宿主管理 |
| `anda mib` 启动后只监听服务 | “命令跑起来了，测试结果在哪” | 明示这是适配服务；补独立 runner 与结果报告 |
| learning feature 与 runtime、MIB 并列介绍 | “打开开关就会持续变聪明” | 只有准备好业务执行器、独立观察与批准后，才展示可用动作 |

主要实现依据：

- [会话提交](../anda_bot/src/engine/agent/runner.rs)：普通会话后台提交，提交失败退避。
- [持久日志](../anda_bot/src/brain/journal.rs)：接受状态、具体 Brain 会话与不确定提交窗口。
- [Brain 客户端](../anda_bot/src/brain/client.rs)：普通记忆状态、召回、Formation、待办独立 API。
- [身份边界](../anda_bot/src/brain/host.rs)：运行时按认证调用者映射，不复用 Bot 全局身份。
- [浏览器入口](../chrome-extension/src/BrainApp.svelte)与[待办](../chrome-extension/src/lib/anda/brain/Inbox.svelte)：现有图谱和持久回复机制。
- [MIB 宿主](../anda_bot/src/mib.rs)：隔离实验、协议接口、部分成本计量，不包含完整评测产品。

## 3. 围绕三个真实任务设计

### 任务 A：不要让我每次重复偏好

例子：“以后代码评审先说风险，最后再说风格问题。”

预期体验：正常聊天 → 后台整理 → 下次相关任务带入偏好。无需用户维护文件，也不要求为记忆建立分类。

成功标准：在新会话、没有重述偏好的条件下，相关任务遵守了正确版本。读取到了旧记录不算完成，当前会话直接复述也不算跨会话记忆证据。

### 任务 B：隔几天回来，接上项目

例子：“继续支付迁移，上次为什么选方案 B？”

预期体验：Anda 检索相关背景，用简短上下文说明继续工作的依据；有冲突时只询问影响当前任务的事实。不能确认就说没找到，不能拼出一段貌似合理的历史。

成功标准：项目、时间、参与者和当前版本正确；找不到时明确暴露缺口。

### 任务 C：旧信息别一直影响我

例子：“上个月是周五发版，现在改到周二。”

预期体验：提炼“原值 → 新值 → 生效范围”，让用户核对；后续默认使用新版本，历史原因可追溯。今天的自然语言纠正只能提交新信息，尚不能冒充已完成的结构化替换或彻底删除。

成功标准：新任务不再使用过时值，同时保留必要历史。若要删除，明确删除范围和结果，见第 7 节。

## 4. 第一次使用：先让用户完成一次有意义的体验

设计目标：用户在一分钟内理解用途并开始第一步；后台整理何时完成由真实状态决定，不承诺一分钟内记住。

**默认路径是零个额外步骤。** 用户照常聊天、处理工作，记忆在后台发挥作用。不要强制做“记住一条偏好”的新手任务，也不要要求先打开记忆面板。下面的体验只在用户选择“了解记忆”或第一次访问空记忆页时展开。

1. 首次成功进入聊天，显示一次可关闭、非阻断的轻提示：

   > Anda 可以把有用的对话整理成长期记忆，之后帮你接着做事。数据默认保存在本机，处理时可能使用你配置的模型服务。
   > **告诉 Anda 一条偏好** · 了解记忆

2. 点击后只填入可编辑的草稿：“记住：我希望你在＿＿时，优先＿＿。”不自动发送，不预填虚构个人信息，不先让用户选“是否启用 Brain”。
3. 用户发送后，正常回应需求。消息旁展示“等待整理”，接到对应收据后显示“正在整理”。显示由宿主驱动，模型文本不能决定状态。
4. 整理完成时展示实际结果。能关联到具体提取项时，显示“已保存：发布说明保留风险段落”；只能确认处理完毕时，显示“对话整理完成”，不能给每一句话打“已记住”。
5. 提供“在新对话中试试”。新会话只带检索问题，不带答案；等待用户触发真实召回。没找到则展示结果和排查入口，不能暗中重复塞入刚才的偏好。
6. 第一次成功后结束引导。此后让记忆融入任务，不每天要求用户“训练大脑”。

处理失败时保留当前工作流与原消息。明确拒绝可提供重试；接受情况不明显示“正在确认保存结果”，先对账，不盲目重复提交。

真正的价值时刻应发生在工作中。例如下周用户说“帮我写这次发版说明”，Anda 给出符合最新偏好的内容，并提供可展开的依据“参考了你的发布说明偏好”。如果只能证明检索到信息，则写“检索到相关偏好”，不能自动标为已采纳；如果这次没有检索依据，不显示装饰性的记忆标记。

记忆状态不挤占主回答；只在失败影响当前任务、发现必须澄清的冲突、或用户主动查问时打断。日常不弹“又记住了一件事”的连续通知。

## 5. “记忆”首页：回答四个问题

首页不设置“智力分数”“记忆质量 98%”或以节点数量代表效果。使用现有组件和样式，桌面与窄屏按同一信息优先级组织。

| 优先级 | 区域 | 展示与动作 |
| --- | --- | --- |
| 1 | **查找记忆** | 自然语言搜索；标明来源、时间与不确定性；模型检索单独标示处理中 |
| 2 | **需要你确认** | 有真实事项才显示；说明为什么问、影响什么，直接回答 |
| 3 | **最近记住 / 最近更新** | 人类可读的记录、来源、范围、状态；进入详情核对、更正 |
| 4 | **关于你 / 进行中的项目** | 按用户任务组织的视图，不把底层 Concept 类型直接变成导航 |

页脚弱化展示“整理中 / 连接异常”；“探索关系”“处理记录”“高级设置”作为次级入口。用户不配置 native runtime，仍应能使用首页的普通记忆能力。

记录详情建议包含：正文、适用人物/项目、来源对话和时间、生效时间、被替代关系、可用操作。缺失来源就显示“来源信息不足”，不能让模型补造来源链接。

空状态根据原因区分：

| 状态 | 文案方向 | 主动作 |
| --- | --- | --- |
| 从未整理出记录 | “先从一条常用偏好开始。” | 写一条偏好 |
| 有任务正在整理 | “正在整理这段对话，完成后再查找。” | 继续聊天 |
| 搜索无结果 | “没有找到这条信息。” | 换个问题 / 补充信息 |
| 记忆服务不可达 | “暂时读不到记忆，已有数据是否正常仍待检查。” | 检查连接 |
| 待办未配置 | “需要确认功能尚未设置。” | 了解用途；不把它渲染为记忆故障 |
| 待办未授权 | “当前账号无法查看这些事项。” | 使用正确账号；不能降级为匿名或借用 owner |

TUI 同样提供 `/memory` 概览和人类可读的任务入口；具体对象编号与 JSON 仅在“技术详情”出现。IM 以自然语言为主，受原有用户和路由权限约束，不假定终端斜杠命令在 IM 也可用。

### 一条记忆的操作合同

以“项目 A 的发布说明先写风险”作为设计示例，不代表现有数据：

| 用户点击 | 必须发生的行为 | 不能完成时 |
| --- | --- | --- |
| 查看来源 | 定位到可授权访问的原对话/信息，不只跳到图谱节点 | 展示来源缺失或权限说明 |
| 更正 | 展示旧值、新值、适用范围和生效时间，确认后提交可信变更 | 标明仅提交了更正信息，保留处理中状态 |
| 用于当前任务 | 把用户选定的内容和出处交给当前任务，记录明确的用户选择 | 不自动执行任务或扩展权限 |
| 不再使用 / 删除 | 解释停用与删除的差异、受影响范围，确认后执行并验证 | 说明未完成部分，不能直接把卡片隐藏后宣称成功 |

更新请求若只说“改成周二”，先利用当前选中记录的上下文；只有对象或范围确实不清楚时才追问一个问题。避免每次更正都要求用户填写分类表单。

## 6. 记忆状态必须有证据等级

| 用户可见状态 | 可以据什么显示 | 不能据什么显示 |
| --- | --- | --- |
| 记忆服务已连接 | 当前调用者可读取普通记忆状态 | runtime.configured、模型口头确认 |
| 已收到，等待整理 | 宿主持久化了待处理窗口 | 仅显示一条聊天回复 |
| 正在整理 | 对应 Formation 被接受/运行中 | 全局 high-water mark |
| 对话整理完成 | 对应 Brain conversation 完成 | 全局“当前空闲” |
| 已保存某条信息 | 可关联的提取记录和来源 | 仅某次 Formation 完成 |
| 已检索到相关记忆 | 本次召回实际返回的记录/包 | 图谱里有相似节点 |
| 本次任务受益 | 可解释的使用证据或用户反馈，标明证据来源 | Recall 交付收据 |
| 自动策略已验证 | 独立观察、有效对照与批准材料 | 模型自评、机制测试通过 |

这是产品呈现约束，不要求把证据术语全展示给用户。日常只展示下一步需要的信息，点开“为什么这样显示”才查看细节。

## 7. 控制感：纠正、暂停、删除

以下是待开发能力，当前不能仅通过 prompt 宣称已支持。

**纠正**：先生成明确的差异，例如“默认发版日：周五 → 周二；适用：项目 A；从今天起”。用户确认后通过可信写入接口修改，保留被替代关系；不存在确定的写入 API 时，只能称为“已提交更正信息”。

**不参与长期记忆**：会话开始前可选择。必须由宿主阻止该会话内容及衍生摘要、工具输出进入 Formation，并明确是否也禁止 Recall。工作历史、日志、附件和模型服务记录是否保留须分别说明，不能统称“无痕”。切换只作用于明确的边界，已提交窗口要展示处理情况。

**删除**：先显示将删除的记忆、来源与派生关联，以及不会自动删除的聊天、日志、备份、模型服务数据。确认后返回删除结果，检索与缓存失效要一起验证；后台重新整理旧聊天不能无提示复活该信息。无法保证这一点前，不发布“彻底忘记”按钮。

这些能力的重要性高于给用户更多图谱操作。发布范围可分期，但文案不能提前承诺。

## 8. “需要确认”：把配置负担交给产品

先回答“我要确认什么”，再决定是否配置运行时。不能仅安装 inbox adapter 就宣称系统已经能主动发现所有矛盾或提醒所有事情；事项产生仍需要明确的 Watch/Decision 来源。

**当前对话中的澄清直接问，不要求开启待办。** 只有需要跨会话保留、后台等待、重启恢复的问题，才进入持久“需要确认”。这样用户第一次遇到矛盾时，不会被引导去配置另一个子系统。

拟新增的 setup 流程：

1. 展示用途和支持范围：仅记忆事项在应用内请求确认；定时提醒仍走现有 cron 产品。
2. 使用真实本地 owner 认证身份生成最小映射和 inbox 配置。展示本次会写哪些文件、赋予什么能力；不要求用户复制 CWT subject。
3. 检查已有 runtime_config 和环境变量覆盖。自定义配置不覆盖；采用导入/合并预览。维护配置版本、备份和回退说明。
4. 在加载 Space 前完整校验。必要的重启应让用户感知并可延后；失败时保留可恢复配置，不能悄悄关闭原有绑定继续宣称成功。
5. 验证调用者映射和收件箱可读，若没有真实事项，显示“已设置，目前无待确认事项”。演示事项需明确标记，并与真实决策记录隔离。

回答体验：事项标题 → 为什么询问 → 一个问题 → 回答。技术键、分页游标和原始 JSON 折叠。发送前本地持久化事件键与正文，网络不确定时只重发原请求；想修改内容须使用新的逻辑事件并遵循事项状态。提交成功只表示回答被接收，不显示“任务已执行”。

不要自动给其他可信用户配置同一队列，不提升外部 IM 用户，不恢复已撤销 grant，不为普通回答授予执行权限。无实际事项时不向用户推送“你的记忆需要关注”类空通知。

## 9. MIB 产品化：记忆实验室

### 9.1 三种动作明确分开

| 动作 | 用户的问题 | 需要模型吗 | 当前基础 / 拟议能力 |
| --- | --- | --- | --- |
| **检查连接** | “服务能不能读到？” | 否 | 拟提供普通记忆概览；当前 MIB `describe` 已可检查协议声明 |
| **试一次跨会话记忆** | “这条信息能不能找回？” | 是，普通会话和召回可能付费 | 可按指南手动体验；自动化引导待开发 |
| **对比记忆效果** | “同样任务有无记忆差多少？” | 是，且包含后台记忆处理 | 独立 runner、预算与报告待开发 |

普通用户无需先测试再聊天。实验室对开发者开放，默认使用合成数据和隔离临时空间；个人记忆只在用户明确选择后进入特定实验。实验结果不自动写回日常记忆。

MIB 对大多数用户应是产品背后的质量保证：维护者在预先批准的评测预算下得到回归证据，再向用户公布有适用范围的结果。让每位用户自行安装评测器、比较模型和读 JSON，不是基础产品的使用步骤。

当前 `anda mib` 是隔离适配服务：监听不代表评测完成；GET describe 不验证模型凭证能用，不证明 Formation/Recall 正常，也不会生成成绩。

### 9.2 未来“一次点击得到有意义的报告”

流程：选一个目标 → 查看实验计划和开销边界 → 显式开始 → 展示阶段进度 → 阅读报告和失败样例。

首个模板选“跨会话偏好与更新”，用冻结的合成题目覆盖：稳定偏好、事实更新、同名项目区分、信息不足时不编造。模板带固定评分规则，尽量使用结构化输出和确定性评分；不得用被测 Agent 自评代替独立业务证据。

评测方式必须让用户选对：

- **只对比记忆层（Track A）**：冻结同一业务 agent/model/prompt/tools，由 runner 控制差异，比较 persistent 与 no_memory。
- **评估 Anda 适配器（Track B）**：评估现有有界模型步骤与 runner 执行工具的组合，不冒充完整 daemon、IM、cron 或桌面工作流测试。

每一对用例使用同一任务与采样约束，独立 run 命名空间；会话边界清空短期上下文。记录模型、提示、工具、数据和预算标识；无种子支持时如实披露，并用重复配对和不确定区间处理随机性。协议重试保持相同 request_id 和正文；宿主重启后整组重开，不能把旧结果接到新 epoch。

### 9.3 预算先于“开始测试”

当前宿主只有局部输出/Recall 上限、操作与空闲超时，`accounting_complete=false`。因此今天不能显示“最多花 ¥X”或“超出绝不会收费”。未测费用显示未知，不能记作 0。

发布一键付费评测前，需补齐：所有模型阶段的共享预算、调用前预留、取消和超时的后续成本处理、provider 重试可观测性，以及独立观察端成本。无法提供硬金额上限时，只能在高级实验明确展示已能保证的调用/时间边界与剩余不确定性，再让用户主动发起。

### 9.4 报告先解释结果，再给指标

报告固定回答：

1. 在什么任务上、对比了什么；有效用例数与总用例数是多少。
2. 成功率、过时信息率、无法回答时的诚实率如何变化；显示差值和不确定性。
3. 展示有代表性的成功与失败样例，链接实际执行记录。
4. 已测 token/延迟/费用有哪些，缺哪些；每个 run 仅取最后的累计成本快照，再跨独立 runs 聚合。
5. 给出“本样本支持 / 证据不足 / 本样本退化”的结论；失败或取消的运行单独列出，不悄悄从分母消失。

不能把一次简单偏好演示称为 benchmark，不能把 persistent 组称为已配置的 normal 学习组，不能把机制 fixture 写成“提升 X%”。样本少或计量缺失时报告仍有用，但结论必须相应收窄。

## 10. 自动学习：从具体业务模板进入

不要在普通设置页放“开启自主学习”总开关。用户无法知道会学什么、改什么、花多少、什么时候停止。

未来入口应是“改善一个重复工作流”，例如某个已经支持 inspect/prepare/commit 的业务任务。显示：当前做法 → 建议变化 → 验证范围 → 独立观测 → 是否允许应用 → 回退。每一步都有实际状态和下一步。

当前仅有 `workflow_http_v1` / `tool_workflow.precondition.v1` 的绑定基础。产品向导只有在支持的 executor、独立 observer、冻结 source、校准和完整预算均满足时，才允许创建真实学习任务。普通聊天、shell 和 IM 不能被一个 UI 开关升级成学习执行器。

默认在隔离环境验证，应用到业务另有明确授权。撤销后不因重启恢复授权。暂无满足条件的业务模板时，入口解释准备条件，不展示可点击但无法兑现的“开始变聪明”。

## 11. 可实施的交付顺序

| 阶段 | 交付物 | 主要改动位置 / 依赖 | 验收门槛 |
| --- | --- | --- | --- |
| P0：能理解、能开始 | 普通记忆入口、状态解释、体验指南、MIB 定位 | CLI/TUI、系统指令、README、集成文档 | 未配置 runtime 也能看普通记忆状态；指南不调用模型 |
| P1：知道刚才发生了什么 | 消息旁的整理状态、来源可追踪的最近记录、失败与不确定状态 | journal → 按 caller/session 授权的宿主查询 → gateway/TUI/浏览器；必要时补 Brain 来源投影 | 不用手输 ID；不把处理完成说成每条事实已保存 |
| P2：看得懂、改得动 | 记忆首页、范围明确的更正、会话记忆策略、删除与防复活 | 有来源的查询投影、可信变更接口、派生与缓存失效；先明确 Brain API 缺口 | 源数据可核对；更正可追踪；隐私策略由宿主执行 |
| P3：需要时再主动 | owner setup、真实事项创建、简单回答、持久重试 | 配置管理、身份映射、native Watch/Decision 创建入口、Inbox | 生成最小权限配置；不越权、不重复逻辑回答 |
| P4：证明是否有帮助 | 隔离评测 runner、冻结样本、预算、配对报告 | 现有 MIB 两协议、实验目录与清理、分阶段计量、独立评分 | 可复现条件与局限明确；成本未知不伪装成完整 |
| P5：受控业务学习 | 已验证工作流模板、独立观察、审阅与回退 | 业务服务、Brain learning、校准与授权 | 真正执行和观察都接通后再开放自动应用 |

P1 的投影复用现有 journal，不另造一套记忆真相库。新增 API 返回最小用户视图；来源在服务端按认证主体与原会话范围过滤，不能接受模型传入的 owner。旧记录没有新字段时显示“记录信息不足”，不伪造迁移证明。

P2 的持久字段必须检查 schema/index/version/default；原生权限不能由前端可见性代替。已有高级配置保留原语义，默认升级不写入新 grant、不启动评测、不自动更改任务权限。图谱与 `/brain` 显式技术子命令继续可用。

## 12. 验收场景与指标

发布前必须覆盖：

- 新用户只配置普通模型，能完成偏好 → 后台整理 → 新会话检索；未配置 inbox 不影响入口。
- 记忆正常但 inbox 返回 403 时，分别呈现，不将全部记忆判为损坏，也不切换身份重试。
- Formation 完成却未提取该偏好时，不出现该事实“已保存”标记。
- 新信息更新旧信息后，新会话不会因为历史被召回而继续使用过时值。
- 接受确认丢失时，展示不确定并对账；不以再次点击导致重复提交。
- 用户看不到其他调用者的来源、待办、计数和任务路由；外部 IM 用户不升级。
- 用户暂停长期记忆后，工具输出、摘要和异步任务仍遵循已声明的会话边界。
- 删除后重新整理旧会话，不无提示恢复已删除信息；删除范围在 UI 中准确表达。
- MIB 无效/取消样例、重启、费用缺测都出现在报告里；成本累计快照不重复相加。
- 中文和英文入口一致；窄屏可完成查看、更正、回答；状态对色觉和读屏用户可理解。

度量先验证用户价值：首次开始记忆体验的完成率、首次跨会话检索成功率、纠正后过时信息复发率、用户为同一项目重复补充背景的频率。对后两项需明确采样和评估方法，不能只通过节点数推算。

技术指标用于定位问题：状态接口失败率、各阶段耗时分布、未知接受状态占比、待确认事项完成率、评测无效率与计量完整率。默认只在本地诊断；收集产品分析数据另行设计选择权和最小化数据范围。

### 发布前的小规模可用性验证

招募 5 位未接触 Brain/MIB 的目标用户，使用预先准备好的隔离测试账号和合成项目。在没有讲解实现概念的条件下，让他们完成“开始聊天、下次接续、更正偏好、确认是否保存、处理失败”五个任务；最后请他们用自己的话解释记忆用途，以及 MIB 是否是必需的。

建议通过门槛：至少 4 人能在一分钟内说明用途并开始，不需要问“runtime 是什么”；每位用户均能区分“服务已连接”与“这条信息已保存”。这些是拟定验收目标，尚未验证；5 人测试用于发现交互问题，不代表统计上的效果证明。若多数人仍需打开技术文档才能完成日常任务，应继续简化入口，不通过增加说明文字来掩盖交互缺口。

## 13. 建议首发范围（待实现）

建议先实现 P0，形成一批独立可发布的改进。以下命令目前不存在或行为不同，均为拟议合同：

- `anda memory guide`：离线入门，不加载身份、不创建 home、不启动服务、不调用模型。
- `anda memory` / `anda memory status` / `anda memory --json`：分别读取普通记忆和可选 runtime 状态；不自动启动 daemon，不调用模型。
- TUI `/memory` 与裸 `/brain`：默认展示普通记忆概览；`/memory help` 给可操作的体验路径；显式 `/brain inbox/status/...` 保留技术能力。
- 普通记忆状态失败与空数据区分；待办无权限不吞掉普通记忆状态；状态请求有时间上限。
- 系统指令解释默认记忆、异步保存和自然语言更正的边界；中英文入口文档同步。

首发范围不包含来源卡片、严格的逐事实保存证明、一键 runtime 配置、隐私会话/删除、自动 MIB runner、完整预算或业务自动学习。它们是上面的后续交付内容，不能写成当前已上线能力。

P0 是降低认知门槛的入口版本，不能作为整个产品化项目的完成条件。达到“用户能自主理解、验证、纠正”的可用版本至少需要 P0–P2；P3–P5 面向确实有持久事项与业务评测需求的用户逐步开放。
