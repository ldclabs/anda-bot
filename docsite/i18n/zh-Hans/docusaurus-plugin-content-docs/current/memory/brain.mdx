# Brain 记忆大脑

## 从一次聊天开始

运行 `anda memory guide` 查看离线介绍。日常记忆无需额外设置 Brain 或 MIB。告诉 Anda：“记住：我喜欢简短的发布说明，但要保留风险段落。”等后台整理后，用 `/new` 开新对话询问。助手说“记住了”不等于保存收据。

`anda memory` 和 TUI `/memory` 不调用模型，只查看连接与处理状态。浏览器“记忆”工作区展示有来源的记录和对话活动，“探索关系”打开图谱。来源映射及摘要都匹配时可跳转原消息。搜索可能调用模型，不自动重试。

请核对记录的“更正”“停用”“删除”预览后再确认。停用保留已归档的记录，删除清除预览中的原生集合。来源排除在重启后仍有效，处理 Notes 会清空。原聊天、文件、日志、备份和已交付的上下文仍保留。来源不完整或范围不受支持时，此入口会拒绝操作。更正时先选择是哪种修改：“是我说错了”取代你之前的说法；“情况变了”从现在起记录新值，旧值在它的时段内仍然成立；“你记错了”让 Brain 重读原始消息并修复这条记录。删除会报告擦除计划：已完成、部分完成（有存储面无法验证）或被法律保留阻止。

输入框可为新对话选择记忆模式。CLI 使用 `anda agent run --memory-mode no-store --prompt '…'` 或 `--memory-mode off`。它们约束 Brain/Notes 自动读写及后台提交，不是聊天或服务商的无痕模式；受限模式也拒绝子任务、书签及 cron 变更。

需要跨会话保留确认问题时，使用“设置记忆待办”或 `anda memory inbox setup`。预览并确认配置后，显式运行 `anda restart`。自定义文件和环境覆盖会保留。对记录订阅后，变化会触发真实原生待办。TUI 使用 `/memory inbox`、`/memory answer <编号> <正文>`、`/memory retry <编号>`，重试沿用原事件与正文。

使用 `anda memory inbox` 读取待办，按输出提示运行 `anda memory inbox --cursor <next_cursor>` 读取下一页。使用 `--json` 时，游标位于 `result.next_cursor`。

MIB 对照评测和业务学习是独立的高级功能。含 MIB 的构建可运行 `anda memory evaluate plan --help` 查看隔离评测流程，费用可能不完整。普通记忆对照不能充当业务学习批准，也不能证明实际提升。


Anda Brain 是 Anda Bot 的长期记忆系统。它不是普通向量库，也不是一份越写越长的 Markdown 记忆，而是一颗面向智能体的记忆大脑。

Brain 会把对话、文件、工具结果和频道上下文转化为一个持续生长的 Cognitive Nexus：里面有用户、项目、偏好、事件、决策、时间线，以及这些节点之间的关系。

## 三阶段循环

### Formation

Formation 会把有价值的对话和工作结果编码为结构化记忆。它关心的不只是“这句话出现过”，而是：谁、什么项目、什么偏好、什么决策、什么事件，以及它们在什么时候发生。

### Recall

Recall 让 Anda 可以用自然语言向记忆图谱提问。召回结果应该解释当前任务，而不是只返回相似文本片段。

### Maintenance

Maintenance 会在后台巩固碎片、合并重复信息、降低陈旧知识的影响，并在事实变化时保留演化时间线。

## 如何教会 Anda

你不需要维护记忆文件。更好的方式是把稳定事实、变化和偏好直接说清楚。

```text
记住：我喜欢简短的发布说明，但要保留风险段落。
这个 workspace 的默认模型 provider 已经从 A 改成 B。
以后我们提到 Alice，指的是移动端团队的设计师。
你还记得支付迁移项目的背景吗？
```

## 好记忆的特点

- 有上下文：项目、人物、文件、频道或时间范围明确。
- 有演化：偏好变化时说明旧状态和新状态。
- 有边界：临时信息可以说清楚只是本次任务有效。
- 有纠正：当 Anda 记错时直接指出正确版本。

## 本地和模型 provider

记忆图谱数据默认保存在本机 `~/.anda/db`。模型 provider 仍可能参与记忆形成、召回支持和摘要处理，所以请根据隐私需求选择 provider 和 endpoint。

想让某个 provider 优先承担记忆相关任务，可以添加 `brain` 标签：

```yaml
model:
  providers:
    - family: anthropic
      model: "deepseek-v4-pro"
      api_base: "https://api.deepseek.com/anthropic"
      api_key: "YOUR_API_KEY"
      labels: ["pro", "brain"]
```

## 可选原生运行时

通过 `brain.runtime_config` 指定可信 JSON/YAML，路径相对配置目录解析；`BRAIN_RUNTIME_CONFIG` 优先。重启后在首次加载 Space 前安装绑定。浏览器记忆待办及 TUI `/brain inbox`、`/brain status`、`/brain formation <id>` 保留真实调用者身份。读取不授予执行权限，回答重试须保留相同事件键和正文。Recall 收据只证明交付，Formation 接受不等于完成。`learning` 与 `mib` 独立；语义求值、utility、trust、自动学习均需显式原生配置与权限。现有 IM 发送接口不是自动动作适配器；MIB persistent 不宣称 normal/ungated 学习或完整计量。每个 Formation 窗口都是带持久回执的 observe 意图，中断的提交会重放同一回执，不会把窗口整理两次。`recall_memory` 会先短暂等待本对话尚未处理完的窗口，并说明哪些仍在处理。`brain_attention` 还会返回你上次查看以来到期的承诺和已触发的 Watch；`brain_feedback` 把助手的自述记录为带归属的证据，而不是评分。

```yaml
brain:
  runtime_config: brain-runtime.yaml
```

旧浏览器令牌无需重新导出即可继续使用：运行时请求保留原用户身份，内嵌 Brain 接受未指定 audience 的令牌，并照常校验签名和有效期。
