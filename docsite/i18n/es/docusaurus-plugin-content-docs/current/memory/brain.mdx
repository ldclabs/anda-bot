# Cerebro de memoria Brain

## Empieza con una conversación

Ejecuta `anda memory guide` para una guía sin conexión. La memoria cotidiana no necesita configurar Brain ni MIB. Indica una preferencia estable, espera al procesamiento y abre otra conversación con `/new` para preguntar qué recuerda. Una respuesta «recordado» no demuestra que el dato esté guardado.

`anda memory` y `/memory` en la TUI consultan estado sin llamar a modelos. El espacio **Memoria** del navegador muestra registros, citas verificadas y actividad; el grafo sigue en **Explorar relaciones**. La búsqueda puede llamar a un modelo y no se repite automáticamente.

Revisa la vista previa antes de corregir, desactivar o eliminar. Desactivar conserva los registros archivados; eliminar purga el conjunto nativo mostrado. Las exclusiones de origen sobreviven al reinicio y se vacían las Notes de procesamiento. Permanecen chats, archivos, registros, copias y contexto ya entregado. Se rechazan ámbitos con fuentes incompletas o no admitidos. Una corrección pregunta primero qué tipo de cambio es: **Lo dije mal** sustituye tu afirmación anterior, **Las cosas cambiaron** registra un valor nuevo desde ahora mientras el anterior sigue siendo cierto para su periodo, y **Lo registraste mal** pide a Brain que vuelva a leer el mensaje original y repare el registro. La eliminación informa su plan de borrado: completado, parcial si una superficie no pudo verificarse, o bloqueado por una retención legal.

El compositor permite elegir un modo para una conversación nueva. En CLI: `anda agent run --memory-mode no-store --prompt '…'` o `--memory-mode off`. Restringen el acceso automático a Brain/Notes; no son navegación privada para chats o proveedores. También bloquean subagentes, marcadores y cambios de cron.

Para conservar preguntas entre conversaciones, usa la configuración de pendientes o `anda memory inbox setup`. Revisa, aplica y ejecuta explícitamente `anda restart`. Se preservan archivos personalizados y variables de entorno. Una suscripción a un registro genera una pregunta real cuando cambia. En TUI: `/memory inbox`, `/memory answer <número> <texto>` y `/memory retry <número>`; el reintento conserva evento y texto.

Lee los pendientes con `anda memory inbox`. Sigue el comando mostrado `anda memory inbox --cursor <next_cursor>` para acceder a la siguiente página. Con `--json`, el cursor está en `result.next_cursor`.

La evaluación MIB y el aprendizaje empresarial son funciones avanzadas independientes. Consulta `anda memory evaluate plan --help` en una compilación con MIB. Los costes pueden ser incompletos. Una comparación de memoria no aprueba el aprendizaje empresarial ni demuestra una mejora general.


Anda Brain es el sistema de memoria a largo plazo que impulsa a Anda Bot. No es una base de datos vectorial simple ni un archivo Markdown en constante crecimiento; es un cerebro de memoria diseñado específicamente para agentes de IA.

El Brain convierte las conversaciones, los archivos, los resultados de las herramientas y el contexto de los canales en un Cognitive Nexus (nexo cognitivo) en constante crecimiento: personas, proyectos, preferencias, eventos, decisiones, líneas de tiempo y las relaciones entre ellos.

## Bucle de tres fases

### Formación (Formation)

La Formación codifica conversaciones útiles y resultados de trabajo en memorias estructuradas. No solo se pregunta si apareció una frase en el chat; pregunta quién la dijo, a qué proyecto pertenece, qué preferencia revela, qué decisión se tomó y cuándo sucedió.

### Recuerdo (Recall)

El Recuerdo permite consultar el grafo de memoria utilizando lenguaje natural. Un buen recuerdo proporciona el contexto necesario para la tarea actual, en lugar de limitarse a devolver fragmentos de texto similares o cercanos.

### Mantenimiento (Maintenance)

El Mantenimiento consolida los fragmentos de información, fusiona los datos duplicados, reduce la influencia del conocimiento obsoleto y preserva las líneas de tiempo cuando cambian los hechos.

## Cómo enseñar a Anda

No es necesario mantener manualmente archivos de memoria. Un mejor enfoque consiste en indicarle claramente a Anda las preferencias, los hechos estables y los cambios que ocurran.

```text
Recuerda: me gustan las notas de lanzamiento cortas, pero conserva una sección de riesgos.
El proveedor de modelos predeterminado para este espacio de trabajo cambió de A a B.
Cuando mencionemos a Alice, nos referimos a la diseñadora del equipo móvil.
¿Recuerdas los antecedentes del proyecto de migración de pagos?
```

## Qué hace que una memoria sea buena

- Contexto: el proyecto, la persona, el archivo, el canal o el rango de tiempo deben estar claros.
- Evolución: cuando cambie una preferencia, indique tanto la versión antigua como la nueva.
- Límites: la información temporal se puede marcar como válida únicamente para la tarea actual.
- Corrección: si Anda recuerda algo incorrectamente, indíquele directamente la versión correcta.

## Datos locales y proveedores de modelos

Los datos del grafo de memoria se almacenan localmente en `~/.anda/db` de forma predeterminada. Los proveedores de modelos pueden seguir participando en la formación de la memoria, el soporte de recuerdo y la síntesis, así que elija los proveedores y puntos de conexión (endpoints) que mejor se adapten a sus necesidades de privacidad.

Para priorizar un proveedor para tareas relacionadas con la memoria, agregue la etiqueta `brain`:

```yaml
model:
  providers:
    - family: anthropic
      model: "deepseek-v4-pro"
      api_base: "https://api.deepseek.com/anthropic"
      api_key: "TU_CLAVE_API"
      labels: ["primary", "brain"]
```

## Entorno nativo opcional

Configura `brain.runtime_config` con un archivo JSON/YAML de confianza relativo al directorio de configuración; `BRAIN_RUNTIME_CONFIG` tiene prioridad. Reinicia para instalar los enlaces antes de cargar el Space. La bandeja Brain del navegador y `/brain inbox`, `/brain status`, `/brain formation <id>` en la terminal conservan la identidad autenticada. Leer no autoriza la ejecución; reintenta respuestas con el mismo evento y texto. Un recibo Recall solo prueba la entrega; aceptar Formation no significa completarlo. La función `learning` es independiente de `mib`; semántica, utility, trust y aprendizaje automático requieren configuración nativa explícita. Los transportes IM actuales no son adaptadores de acción automática. MIB persistent no declara aprendizaje normal/ungated ni costes completos. Cada ventana de Formation es una intención observada con un recibo duradero, así que un envío interrumpido reproduce el mismo recibo en lugar de procesar la ventana dos veces. `recall_memory` espera primero brevemente las ventanas pendientes de la propia conversación e indica cuáles siguen en proceso. `brain_attention` también devuelve compromisos vencidos y watches disparados desde la última consulta, y `brain_feedback` registra el informe propio del asistente como evidencia atribuida, nunca como una calificación.

```yaml
brain:
  runtime_config: brain-runtime.yaml
```

Los tokens antiguos siguen funcionando sin volver a exportarlos: las solicitudes conservan la identidad original y el Brain integrado acepta un token sin audiencia, verificando igualmente su firma y su caducidad.
