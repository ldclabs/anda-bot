# تكوين بيئة التشغيل

يقوم Anda بتخزين حالة بيئة التشغيل في `~/.anda` افتراضياً. ملف التكوين الرئيسي هو `~/.anda/config.yaml` ، ويتم إنشاؤه تلقائياً عند التشغيل الأول. يقع تكوين خادم MCP الاختياري في `~/.anda/mcp.json`.

## مزودو النماذج

يجب أن يتضمن المزود النشط (active) العائلة (`family`)، والنموذج (`model`)، ورابط قاعدة API (`api_base`). يمكن كتابة مفتاح `api_key` في ملف التكوين أو تركه فارغاً وتقديمه عبر متغير بيئة.

```yaml
model:
  active: "deepseek-v4-pro"
  providers:
    - family: anthropic
      model: "deepseek-v4-pro"
      api_base: "https://api.deepseek.com/anthropic"
      api_key: "YOUR_API_KEY"
      labels: ["pro", "brain"]
      disabled: false
```

متغيرات بيئة مفتاح API للنموذج المدعومة هي:

```text
OPENAI_API_KEY
ANTHROPIC_API_KEY
GEMINI_API_KEY
GOOGLE_API_KEY
DEEPSEEK_API_KEY
MINIMAX_API_KEY
MIMO_API_KEY
MOONSHOT_API_KEY
KIMI_API_KEY
BIGMODEL_API_KEY
GLM_API_KEY
```

## الإعدادات العامة للمستوى الأعلى

| الإعداد | الغرض |
| --- | --- |
| `addr` | عنوان البوابة المحلية، الافتراضي هو `127.0.0.1:8042`. |
| `sandbox` | إذا تم تمكينه (true)، فسيتم تشغيل أوامر shell تحت `~/.anda/sandbox`. |
| `https_proxy` | البروكسي المستخدم لطلبات النموذج والقنوات. |
| `model` | مزودو النماذج للوكيل ودماغ الذاكرة (Brain). |
| `transcription` | مزود خدمة الترانسكريبت للمدخلات الصوتية والملفات الصوتية المرفقة. |
| `tts` | مزود خدمة توليد الصوت (TTS) للمخرجات الصوتية. |
| `channels` | تكوينات Telegram و WeChat و Discord و Lark/Feishu والقنوات الأخرى. |

## خوادم MCP

يمكن لـ Anda Bot الاتصال بخوادم MCP عبر عمليات stdio الفرعية أو نقاط نهاية HTTP. ضع تكوين MCP المحمول في `~/.anda/mcp.json` ، ثم شغّل `anda mcp reload` (أو أعد تشغيل daemon). يقبل الملف كلاً من المفاتيح الجذرية `mcpServers` و `servers` لمساعدتك في لصق التكوينات من الأدوات المتوافقة الأخرى مع MCP مع الحد الأدنى من التعديلات.

```json
{
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "$ANDA_WORKSPACE"]
    },
    "remote": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${secret:MCP_REMOTE_TOKEN}"
      }
    }
  }
}
```

تظهر أدوات MCP البعيدة كأدوات Anda ملقبة بـ `mcp_<server_id>_<remote_tool>`. تدعم سلاسل التكوين توسيع متغيرات البيئة `$VAR` و `${VAR}`، مع `${VAR:-default}` لمتغير قد لا يكون معيّناً، و`${secret:NAME}` لسر (انظر قسم «الأسرار» أدناه). كما أن `ANDA_HOME` و `ANDA_WORKSPACE` مدمجتان بشكل افتراضي. بالنسبة لخوادم stdio، يتم تشغيل الأمر `command` مباشرة بدون shell؛ وعند حذف `cwd` ، يتم استخدام مساحة عمل Anda الأولى. وإذا تم حذف `type` ، يقوم Anda باستنتاج `stdio` من معلمة `command` أو `http` من عنوان URL.

يُحمَّل كل إدخال على حدة، ولا يمنع MCP أبدًا بدء تشغيل الـ daemon: يُتخطّى الإدخال غير الصالح للاستخدام (متغير بيئة غير مُعرَّف، أو `type` غير مدعوم مثل `sse` المُهمَل، أو معرّف مكرر) مع تسجيل تحذير في سجل الـ daemon، وتُحمَّل الخوادم الأخرى كالمعتاد. تتصل الخوادم في الخلفية بعد بدء الـ daemon، لذلك لا تؤخره نقطة نهاية بطيئة أو أول تنزيل عبر `npx -y`؛ أضف `"startup": "eager"` إلى إدخال لاكتشاف أدواته قبل أن يُعلن الـ daemon جاهزيته. تحصل خوادم stdio على `PATH` الموسّع نفسه الذي تستخدمه أداة shell، لذا يُعثر على `npx` و`uvx` وأوامر Homebrew حتى عندما يعمل الـ daemon كخدمة تسجيل دخول؛ لكن هذه الخدمة لا ترى المتغيرات المُصدَّرة في ملف تعريف الـ shell لديك، لذا تحتاج مراجع `${VAR}` إلى وجود المتغير في بيئة الـ daemon نفسه.

يمكن للإدخال أيضاً ضبط طريقة تشغيل خادمه. `timeouts` بالثواني، كل منها بين 1 و 86400: `setup_secs` للاتصال (90 افتراضياً)، و `list_secs` لسرد الأدوات (30)، و `request_secs` لطلب واحد (180)، و `call_secs` لاستدعاء أداة كاملاً (600). يحدد `concurrency` الأدوات التي يمكن تشغيلها معاً: `serial` (افتراضي)، أو `read_only_parallel` (الأدوات التي يصفها الخادم بأنها للقراءة فقط)، أو `parallel`. و `limits.output_text_bytes` هو النص الذي يتلقاه الوكيل من نتيجة واحدة، بين 256 و 1048576 (32768 افتراضياً). يحدد `lifecycle` كيفية التفاوض على مراجعة البروتوكول (`auto` أو `discover` أو `initialize`)، ويتيح `tasks` (`{"max_wait_secs": 900}`) لأداة طويلة التشغيل أن تعيد مهمة يستطلعها Anda حتى تكتمل. يحصل الخادم المحلي على بيئة daemon كاملة، إلا مع `"inherit_env": false` الذي لا يمنحه إلا أساسيات المنصة (`PATH` و `HOME` و `TMPDIR` وما شابهها) و `env` الخاص به، فلا يصل إليه أي سر آخر من بيئة daemon. أنت من يغيّر هذه الإعدادات، في `mcp.json` أو صفحة MCP أو عبر `anda mcp options`، لا أدوات الوكيل.

يمكن للوكيل أيضاً إضافة خادم إلى بيئة التشغيل باستخدام `add_mcp_server`. قم بتعيين `persist: false` للـ daemon الحالي فقط، أو `persist: true` لحفظ الخادم في `~/.anda/mcp.json` لإعادة التشغيل في المستقبل. تتطابق حقول الخادم مع إدخال `mcp.json` : `type` و `command` و `args` و `env` و `cwd` و `url` و `headers` و `enabled` و `include` و `exclude` ، بالإضافة إلى الحقول الخاصة بالأدوات `id` و `persist`. يتيح `manage_mcp_server` للوكيل عرض الخوادم مع حالتها وآخر خطأ فيها وإعادة الاتصال بأحدها؛ أما تفعيل خادم أو تعطيله أو إزالته أو تسجيل الخروج منه فيطلب موافقتك أولاً.

### إدارة الخوادم باستخدام `anda mcp`

```bash
anda mcp list                                         # حالة كل خادم وأدواته وآخر خطأ فيه
anda mcp get github                                   # خادم واحد وأدواته
anda mcp add context7 -- npx -y @upstash/context7-mcp
anda mcp add docs --url https://docs.example.com/mcp --header 'Authorization: Bearer ${DOCS_TOKEN}'
anda mcp add-json notes '{"type":"http","url":"https://notes.example.com/mcp"}'
anda mcp login linear --url https://mcp.linear.app/mcp  # تسجيل الدخول عبر OAuth؛ يطبع --no-browser العنوان
anda mcp tool github delete_repository --hide         # إخفاء أداة عن الوكيل
anda mcp secret set DOCS_TOKEN                        # وأيضاً: secret list و secret unset
anda mcp disable context7                             # وأيضاً: enable و remove و reconnect و logout و reload
anda mcp options github --call-timeout 900            # الإعدادات المتقدمة؛ `default` يمسح إحداها
anda mcp import --dry-run                             # خوادم مُعدّة في تطبيقات أخرى
anda mcp import github notes=work-notes --from cursor # استيرادها؛ دون أسماء يستورد كل جديد
anda mcp events github                                # الأحداث التي يبلّغ عنها الخادم
anda mcp triggers                                     # أتمتة الأحداث؛ وأيضًا: add وget وpause وresume وdelete
```

عندما يعمل daemon يمر كل أمر عبره ويُطبَّق التغيير فوراً: يُعاد تشغيل الخادم الذي تغيّرت إعدادات اتصاله، ويستمر في العمل الخادم الذي لا يمس تغييره الاتصال (حقل لا يقرؤه Anda مثلاً). يُعاد الاتصال بالخوادم الفاشلة في الخلفية بفواصل تتدرج من 30 ثانية إلى 30 دقيقة، ويُحفظ السبب ليعرضه `list`. من دون daemon تعدّل الأوامر `add` و `add-json` و `remove` و `enable` و `disable` و `tool` و `approval` و `external-users` و `secret` و `options` و `import` و `logout` الملفات مباشرة، ويسري التغيير عند بدء daemon. يعرض `list` أيضاً الإدخالات التي تم تخطيها وسبب ذلك، ويطبع `--json` أي نتيجة بصيغة JSON. تحافظ التعديلات على الحقول التي لا يقرؤها Anda وعلى مراجع `${VAR}` والمفتاح الجذري للملف؛ ويحذف `remove` أيضاً بيانات تسجيل الدخول المحفوظة للخادم ما لم تمرّر `--keep-credentials`. لا يراقب Anda ملف `mcp.json`: بعد تعديله يدوياً شغّل `anda mcp reload`. يُحفظ مصدر كل خادم وآخر خطأ فيه وتعريفات الأدوات والتعليمات التي راجعتها وعدد مرات استدعاء أدواته في `~/.anda/mcp_state.json`.

### صفحة MCP

يدير Anda Desktop (MCP في الشريط الجانبي) ولوحة تحكم الإضافة (`#mcp`) الخوادم نفسها. تسرد الصفحة كل خادم مع حالته، وتعرض آخر خطأ فيه واستخدامه وتعليماته؛ وأدواته مع سياسة الموافقة لكل منها وتلميحات الخادم وما تغيّر منذ مراجعتك؛ وتسجيل الدخول؛ والأسرار التي يستخدمها؛ ومُدخله مع إخفاء الأسرار. تقبل الإضافة عنوان URL مع ترويسات، أو أمراً مع متغيرات بيئة، أو إعدادات ملصوقة من تطبيق آخر. وهي تعرض سطر الأوامر كاملاً قبل تشغيل أي شيء، وتختبر الاتصال، وتحفظ افتراضياً قيم الترويسات والرموز المميزة والمفاتيح كأسرار، فلا يبقى في `mcp.json` إلا مراجع `${secret:...}`. الخادم الذي يطلب OAuth يفتح صفحة تسجيل الدخول في متصفحك.

تستورد قائمة الإضافة أيضاً خوادم من تطبيقات أخرى وتتصفح MCP Registry (انظر أدناه)، ويعدّل تبويب الإعدادات الإعدادات المتقدمة.

في Anda Desktop، يفتح رابط على شكل `anda://mcp/install?name=<id>&config=<base64url JSON>` نافذة الإضافة بهذه الإعدادات مع تحذير للتحقق مما تشغّله. لا يُحفظ شيء حتى تضيفه، ولا يستطيع الرابط تغيير خادم موجود.

### الاستيراد من تطبيقات أخرى

يقرأ `anda mcp import` و«استيراد من تطبيقات أخرى» في صفحة MCP إعدادات MCP في Claude Desktop و Claude Code (`~/.claude.json`) و Cursor و VS Code (و CLI الخاص بـ GitHub Copilot، `~/.copilot/mcp-config.json`) و Windsurf و Codex (`~/.codex/config.toml`)، وملفات المشاريع (`.mcp.json` و `.cursor/mcp.json` و `.vscode/mcp.json`) في المشاريع التي يعرفها Claude Code وفي الدليل الحالي (للـ CLI) أو مساحة عمل daemon. تُقرأ هذه الملفات فقط ولا تُغيَّر أبداً.

```bash
anda mcp import --dry-run                    # ما سيصبح عليه كل خادم
anda mcp import                              # كل الخوادم الجديدة على Anda
anda mcp import github notes=work-notes      # المسماة فقط؛ NAME=ID يعيد التسمية
anda mcp import --from cursor --keep-plaintext
```

يُعرض كل خادم مع ما سيفعله استيراده: جديد؛ أو يُعاد تسميته إذا كان اسمه مستخدماً لخادم آخر؛ أو موجود بالفعل في Anda؛ أو هو الخادم نفسه مثل خادم مُدرج سابقاً؛ أو لا يمكن استيراده (خادم SSE مثلاً) مع السبب. عند الاستيراد يُترجم الإدخال إلى صيغة Anda: تُملأ `${env:NAME}` و `${userHome}` و `${workspaceFolder}` من VS Code، ويُقرأ `serverUrl` من Windsurf وقوائم أدوات Copilot وجداول Codex. تنتقل قيم الترويسات والرموز المميزة والمفاتيح إلى الأسرار ما لم تمرّر `--keep-plaintext`. ويصبح `${input:...}` من VS Code ومتغير البيئة غير الموجود لدى daemon أسراراً يجب تعيينها: يطلبها CLI والصفحة، والخادم الذي لم يُعيَّن سره بعد ينتظره. تحصل الخوادم المحلية المستوردة على `"inherit_env": false`. ما لا يُنقل، مثل `envFile` أو قائمة الأدوات الموافَق عليها تلقائياً، يُذكر مع الخادم.

### MCP Registry

يبحث «تصفح MCP Registry» في صفحة MCP في [MCP Registry](https://registry.modelcontextprotocol.io) الرسمي. يُرسل daemon الطلب بإعدادات الوكيل الخاصة به. الخادم المنشور بنقطة نهاية بعيدة يُثبَّت افتراضياً بتلك النقطة، لأنه لا يشغّل شيئاً على حاسوبك؛ ويمكنك اختيار إحدى حزمه من npm أو PyPI أو OCI (Docker) أو NuGet بدلاً منها، فتعمل كأمر محلي مع `"inherit_env": false`. يطلب نموذج التثبيت متغيرات URL والترويسات ومتغيرات البيئة والوسائط التي يعلنها الخادم؛ والقيمة الموسومة كسر تذهب إلى مخزن الأسرار. يمكنك اختبار الخادم قبل تثبيته. يُظهر Registry أن الخادم منشور، لا أنه آمن: تظل أدواته تسأل قبل التشغيل إلى أن تسمح بها.

### الأسرار

يتوسع `${secret:NAME}` في ترويسة أو قيمة بيئة أو وسيطة أو عنوان URL إلى سر محفوظ في `~/.anda/mcp_secrets.json`، الذي لا يقرؤه إلا مستخدمك، لذا لا يحتوي `mcp.json` على رموز مميزة ويمكن مشاركته أو نسخه احتياطياً كما هو. تتكون الأسماء من أحرف وأرقام و`_`، ويمكن لسر واحد أن يخدم عدة خوادم.

```bash
anda mcp secret set GITHUB_PAT              # يقرأ القيمة دون عرضها
gh auth token | anda mcp secret set GITHUB_PAT
anda mcp secret list                        # الأسماء، وهل عُيّنت، والخوادم التي تستخدم كلاً منها
anda mcp secret unset GITHUB_PAT
```

لا تعرض CLI ولا صفحة MCP ولا الواجهة البرمجية القيمة مرة أخرى: لتغييرها عيّن قيمة جديدة. يُتخطّى الخادم الذي لم يُعيَّن سره، مع تشخيص يذكر اسم السر، ويبدأ بمجرد تعيينه؛ وتعيد القيمة الجديدة تشغيل الخوادم التي تستخدمه. ويحذف حذفُ خادم الأسرارَ التي كان يستخدمها وحده أيضاً، ما لم تمرّر `--keep-credentials`.

### الموافقة على استدعاءات أدوات MCP

يمر كل استدعاء يجريه الوكيل لأداة MCP بفحص موافقة، كما هو الحال مع أوامر shell. تحدّد ذلك سياسة `approval` الخاصة بالخادم، لجميع أدواته أو لأداة واحدة:

| السياسة | متى يسأل الوكيل أولاً |
| --- | --- |
| `auto` (الافتراضية) | ما لم تكن الجلسة تعمل بصلاحية الوصول الكامل. تعمل الأدوات التي يصفها الخادم بأنها للقراءة فقط دون سؤال ما دام تعريفها لم يتغير. |
| `ask` | دائماً، حتى مع الوصول الكامل. |
| `allow` | أبداً، ما دام تعريف الأداة لم يتغير. |

```json
"github": {
  "type": "http",
  "url": "https://api.githubcopilot.com/mcp/",
  "approval": { "default": "allow", "tools": { "merge_pull_request": "ask" } }
}
```

```bash
anda mcp approval github allow                              # جميع أدوات الخادم
anda mcp approval github ask --tool merge_pull_request      # أداة واحدة
anda mcp approval github inherit --tool merge_pull_request  # العودة إلى سياسة الخادم
```

لا تُقرأ السياسة إلا عند استدعاء أداة، لذا لا يؤدي تغييرها أبداً إلى إعادة اتصال الخادم. تعمل المهام المجدولة والأهداف بصلاحية الوصول الكامل، لذا تعمل أدوات `auto` فيها أيضاً. وحيث لا يستطيع أحد الرد على طلب الموافقة، كمحادثة IM أو مهمة مجدولة تصادف أداة `ask`، لا يُنفَّذ الاستدعاء ويُبلَّغ الوكيل بالطريقة التي يمكنك بها السماح به.

تقدّم بطاقة الموافقة لأداة MCP أيضاً خيار السماح دائماً (المفتاح `a` في TUI): يوافق على الاستدعاء ويضبط تلك الأداة على `allow`.

يحتفظ Anda بتعريف كل أداة كما قدّمه الخادم أول مرة. وإذا غيّر الخادم لاحقاً وصف أداة أو مخططها، أو أضاف أداة، تفقد تلك الأداة ما مُنح لتعريفها السابق: يسأل الوكيل عنها حتى مع `allow`، إلى أن توافق على أحد استدعاءاتها أو تقبلها بـ `anda mcp review github` (جميع الأدوات) أو `anda mcp review github <tool>`. يعرض `anda mcp diff github <tool>` ما تغيّر، ويُبرز `anda mcp get github` الأدوات التي تحتاج إلى مراجعة. تُحفظ التعليمات التي يقدّمها الخادم للنموذج بالطريقة نفسها: عندما تتغير يذكر ذلك `anda mcp get` وتعرض صفحة MCP النسختين، إلى أن يقبلها `anda mcp review github`.

لا تستطيع طلبات مستخدمي IM الخارجيين استدعاء أدوات خادم إلا إذا سمح الخادم بذلك (`"allow_external_users": true` أو `anda mcp external-users github on`)، ولا تستطيع أبداً استدعاء أداة تحتاج إلى موافقة: فالمستخدم الخارجي لا يمكنه الموافقة نيابة عنك.

يمكن للمهارات المكتوبة لوكلاء آخرين أن تسمّي أدوات MCP بالشكل `mcp__<server>__<tool>`، ويحلّ Anda هذه الأسماء إلى الأدوات نفسها. لا يُحلّ حرف بدل مثل `mcp__github__*`: اذكر كل أداة.

### أتمتة الأحداث

تبلّغ الخوادم التي تدعم امتداد MCP Events عن أحداث، مثل issue جديدة أو تعليق جديد. تشغّل الأتمتة الوكيل وفق تعليماتك عند وصول حدث. أنشئها من علامة تبويب «الأحداث» في الخادم على صفحة MCP، أو باستخدام `anda mcp triggers add`، أو بطلب ذلك من الوكيل الذي يطلب `create_event_trigger` الخاص به موافقتك أولًا:

```bash
anda mcp events github                         # أنواع الأحداث وطريقة تسليم كل منها ووسائطها
anda mcp triggers add github issue.opened --args '{"repo":"owner/name"}' \
    --instructions "أضف تسمية إلى كل issue جديدة ولخّصها" --batch-window 60
anda mcp triggers get 3                        # حالتها وأحدث تشغيلاتها وأحداثها
anda mcp triggers pause 3                      # وأيضًا: resume وdelete
```

- **أين تذهب النتائج.** الأتمتة التي تُنشأ من صفحة MCP أو من CLI ترد في محادثة خاصة بك تتابعها التشغيلات اللاحقة؛ والتي ينشئها الوكيل ترد حيث طُلبت، في تلك المحادثة أو دردشة IM.
- **التجميع والحدود.** تُعالَج الأحداث التي تصل خلال نافذة التجميع (30 ثانية افتراضيًا، وحتى ساعة) في تشغيل واحد يضم 20 حدثًا على الأكثر. تتوقف الأتمتة مؤقتًا من تلقاء نفسها حين توشك أن تتجاوز حدّها الساعي (`max_runs_per_hour`، و12 افتراضيًا)، وهذا يقطع أيضًا حلقة التغذية الراجعة، كالرد على issue ثم تلقي ذلك التعليق حدثًا جديدًا، وكذلك بعد خمسة تشغيلات فاشلة متتالية. استأنفها حين تكون جاهزًا.
- **الثقة.** بيانات الأحداث تأتي من الخادم ولا يُوثق بها: تعرضها التشغيلات على النموذج بيانات لا تعليمات، ولا تسجّلها على أنها كلامك. لا تحصل هذه التشغيلات على الوصول الكامل الذي تحصل عليه المهام المجدولة: يمكنها استدعاء أدوات القراءة فقط والأدوات المضبوطة على `allow`، ويُرفض كل ما يحتاج إلى موافقة (أداة كتابة في وضع `auto`، أو أمر shell خطِر).
- **التسليم.** يُبقي Anda تدفق push مفتوحًا أو يستطلع الخادم، حسب ما يسمح به نوع الحدث، ويحفظ الموضع الذي بلغه، فتُعاد الأحداث التي وصلت أثناء توقف daemon إن كان الخادم يدعم ذلك، ولا يُشغَّل حدث سبقت رؤيته مرتين. وحين يبلّغ الخادم عن أحداث مفقودة تُظهر الأتمتة ذلك. تنتظر الأتمتة إن كان خادمها معطّلًا أو محذوفًا أو متعثرًا، وتنبّه إن احتاج الخادم إلى تسجيل الدخول، وتستأنف في الحالتين عند عودة الخادم.
- **Webhook عبر dMsg.** بعض الخوادم لا تسلّم الأحداث إلا عبر webhook، ولا يستمع Anda على أي منفذ عام. ضع على إدخال dMsg الإعداد `"events": {"webhook_ingress": true}`: لكل أتمتة من هذا النوع ينشئ Anda نقطة نهاية هناك، ويشترك الخادم فيها، ويجدد الاشتراك قبل انتهائه، ثم يعيد dMsg توجيه التسليمات التي تحقق منها. ومن دون مستقبِل تنتظر الأتمتة في الحالة `needs_ingress`.

```json
{
  "mcpServers": {
    "dmsg": { "command": "dmsg", "args": ["mcp"], "events": { "webhook_ingress": true } }
  }
}
```

تُحفظ الأتمتة والأحداث التي تلقتها وتشغيلاتها في قاعدة بيانات daemon؛ ويُحفظ سر توقيع نقطة النهاية في مخزن أسرار MCP.

## هيكل المجلد المحلي

```text
~/.anda/
  config.yaml
  mcp.json
  mcp_secrets.json
  mcp_state.json
  anda-daemon.pid
  channels/
  credentials/ # مخزن أوراق الاعتماد المحلي المشفر للمستخدمين الموثوقين
  db/
  keys/ # ملفات المفاتيح الصريحة أو المفاتيح الاحتياطية لـ Secret Service
  logs/
  bundled-skills/
  sandbox/
  skills/
  skills-manifest.json
  skill-backups/
  skill-trash/
  workspace/
```

| الدليل | محتويات الدليل |
| --- | --- |
| `credentials/` | مخزن أوراق الاعتماد المحلي المشفر. تُخزن هنا المفاتيح الخاصة للمستخدمين الموثوقين كمفاتيح COSE مشفرة. |
| `db/` | قاعدة الذاكرة المحلية والمحادثات وحالة القنوات والمهام المجدولة (cron) والكائنات والبيانات ذات الصلة. |
| `keys/` | ملفات مفاتيح التوقيع المصدرة صراحة أو المفاتيح الاحتياطية لنظام Linux Secret Service. يتم تخزين المفاتيح الخاصة بالهوية لـ daemon و owner في مخزن أوراق الاعتماد الآمن لنظام التشغيل بشكل افتراضي عندما يكون متاحاً. |
| `logs/` | ملفات سجلات daemon و CLI. |
| `channels/` | ملفات حالة تشغيل القنوات. |
| `bundled-skills/` | المهارات المنسقة المدارة بالإصدارات والمثبتة مع تحديثات Anda. |
| `sandbox/` | دليل عزل shell عند تمكين وضع الحماية (sandbox). |
| `skills/` | المهارات الشخصية لبيئة التشغيل التي تم إنشاؤها أو استنساخها أو تعديلها من قبل المستخدم. |
| `skills-manifest.json` | المهارات التي عطّلتها في لوحة التحكم. إذا تعذّر تحليل الملف يُبلَّغ عن الخطأ ويُترك كما هو دون إعادة تعيينه. |
| `skill-backups/` | نسخ بطوابع زمنية من ملف `SKILL.md` لمهارة شخصية تُحفظ قبل كل تحديث. |
| `skill-trash/` | سلة مهملات المهارات الشخصية المحذوفة قبل إزالتها نهائياً. |
| `workspace/` | مساحة العمل الافتراضية لأدوات الملفات والـ shell. |

## حدود الخصوصية

يتم تخزين بيانات الحالة المحلية لـ Anda، ومخطط الذاكرة، والمحادثات، وحالة القنوات، وحالة المهام المجدولة، وسجلات التشغيل، وبيانات مساحة العمل افتراضياً على جهازك الخاص. وتُخزن المفاتيح الخاصة لـ daemon و owner افتراضياً في مخزن أوراق الاعتماد الآمن لنظام التشغيل، بينما تُخزن المفاتيح الخاصة للمستخدمين الموثوقين في مخزن أوراق الاعتماد المحلي المشفر تحت المسار `~/.anda/credentials/`. وقد تتواجد ملفات المفاتيح الصريحة ومفاتيح Linux Secret Service الاحتياطية في دليل `~/.anda/keys/`.

على نظام Linux، إذا لم يكن هناك مزود لخدمة Secret Service متاحاً أو تم إلغاء قفله، فسيرجع Anda إلى استخدام ملفات مفاتيح daemon/owner الخاصة تحت المسار `~/.anda/keys/` ويطبع/يسجل تحذيراً. تظل المفاتيح الخاصة للمستخدمين الموثوقين مشفرة في مخزن أوراق الاعتماد المحلي طالما يمكن تحميل سر هوية daemon. لاستخدام Secret Service لهويات daemon/owner، ابدأ تشغيل المزود وافتح قفله في جلسة D-Bus للمستخدم (على سبيل المثال، `gnome-keyring-daemon --start --components=secrets`) ، وتأكد من تعيين متغير البيئة `DBUS_SESSION_BUS_ADDRESS` لعملية Anda، ثم أعد تشغيل Anda. يمكن لمستخدمي بيئة KDE فتح قفل KWallet بدلاً من ذلك.

ومع ذلك، قد لا يزال مزودو النماذج يتلقون الأسئلة وملخصات نتائج الأدوات وطلبات تكوين أو استدعاء الذاكرة. يرجى اختيار مزودين موثوقين، ونقاط نهاية خاصة، وسياسات بروكسي بناءً على متطلبات الخصوصية الخاصة بك.

:::tip
استخدم المعلمة `anda --home /path/to/.anda` عندما تحتاج إلى بيانات معزولة لهويات مختلفة، أو مشاريع مختلفة، أو لاختبارات معينة.
:::

## Brain runtime

اضبط `brain.runtime_config` على ملف JSON/YAML موثوق بمسار نسبي إلى دليل الإعدادات؛ تكون الأولوية لـ `BRAIN_RUNTIME_CONFIG`. أعد التشغيل لتثبيت الروابط قبل تحميل Space. يحتفظ صندوق Brain في المتصفح وأوامر `/brain inbox` و`/brain status` و`/brain formation <id>` بالهوية الموثقة. القراءة لا تمنح إذن التنفيذ؛ أعد إرسال الرد بالحدث والنص نفسيهما. إيصال Recall يثبت التسليم فقط، وقبول Formation لا يعني اكتماله. ميزة `learning` مستقلة عن `mib`؛ الدلالات وutility وtrust والتعلم التلقائي تتطلب إعداداً أصلياً صريحاً. وسائل IM الحالية ليست محولات إجراءات تلقائية. وضع MIB persistent لا يدّعي تعلم normal/ungated أو اكتمال حساب التكاليف.

```yaml
brain:
  runtime_config: null
```

يمكنك أيضًا ربط خطة ChatGPT Plus / Pro مؤهلة دون مفتاح API:

```bash
anda auth login chatgpt
anda auth accounts
anda auth models <profile-id>
anda auth use <profile-id> <model-slug>
anda auth logout <profile-id>
```

في Anda Desktop، افتح **الإعدادات ← إعدادات الوكيل ← النماذج**. في الإضافة، افتح قسم **النماذج** في صفحة الإعدادات أو إعدادات اللوحة الجانبية. اضغط **Continue with ChatGPT** وأكمل التفويض في المتصفح، ثم اختر **استخدام النموذج المحدد**. في TUI، اضغط **Ctrl+G**. تختار CLI/TUI أول نموذج متاح؛ ويمكن تحديد نموذج عبر `--model <slug>` في CLI. عند عدم إعداد نموذج، يقدم daemon واجهات إعداد مصادَقًا عليها فقط؛ ولا يبدأ Brain أو القنوات أو cron إلا بعد اختيار النموذج. تشترك الواجهات الثلاث في الحسابات وتجديد الرموز ضمن `ANDA_HOME` نفسه. تُشفّر بيانات الاعتماد في `chatgpt/accounts.cose` ولا تُحفظ في config.yaml أو تخزين المتصفح.

انتظر انتهاء المهام والوكلاء الفرعيين قبل تغيير نموذج الخطة. مزودو خطة ChatGPT مخصصون للمالك المحلي فقط؛ وعند تفعيلهم تُرفض طلبات المستخدمين الآخرين والمرسلين الخارجيين عبر المراسلة. يتطلب الصوت والفيديو والنسخ الصوتي مزودين منفصلين. لا يؤدي بلوغ الحد إلى التحويل التلقائي إلى مفتاح API مدفوع. استخدم [إعدادات استخدام ChatGPT](https://chatgpt.com/settings/usage). تبقى إعدادات `.codex/auth.json` القديمة متوافقة، لكن الاتصالات الجديدة ينبغي أن تستخدم تدفق تسجيل الدخول هذا.

على مضيف بعيد أو دون متصفح، شغّل `anda auth login chatgpt --no-browser --port 1455` وأعد توجيه `127.0.0.1:1455` من جهاز المتصفح إلى مضيف daemon. لنقل جلسة، شغّل `anda auth export <profile-id> --output /absolute/path/session.json` (يفصل المضيف المصدر)، وانقل الملف بأمان عبر SSH مع صلاحيات `0600`، ثم شغّل `anda auth import /absolute/path/session.json` على الوجهة. يحذف الاستيراد ملف النقل ويحافظ على معرّف مضيف الوجهة. فعّل النموذج باستخدام `anda auth use <profile-id> <model-slug>`. لا تجدّد الجلسة نفسها على المضيفين معًا.
