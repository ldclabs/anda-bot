# دماغ الذاكرة Brain

## ابدأ بمحادثة واحدة

نفّذ `anda memory guide` لقراءة دليل دون اتصال. لا تحتاج الذاكرة اليومية إلى إعداد Brain أو MIB. أخبر Anda بتفضيل ثابت، وانتظر المعالجة، ثم افتح محادثة جديدة عبر `/new` واسأل عما يتذكره. إجابة «تذكّرت» ليست دليل حفظ.

يعرض `anda memory` و`/memory` في TUI الحالة دون استدعاء نموذج. تعرض مساحة **الذاكرة** السجلات والمصادر الموثقة ونشاط المحادثات، ويبقى الرسم البياني في استكشاف العلاقات. قد يستدعي البحث نموذجًا ولا يُعاد تلقائيًا.

راجع المعاينة قبل التصحيح أو إيقاف الاستخدام أو الحذف. إيقاف الاستخدام يحفظ السجلات مؤرشفة؛ والحذف يمحو المجموعة الأصلية المعروضة. تبقى استثناءات المصادر بعد إعادة التشغيل وتُصفّر Notes المعالجة. تبقى المحادثات والملفات والسجلات والنسخ الاحتياطية والسياق الذي سُلّم سابقًا. تُرفض النطاقات ناقصة المصادر أو غير المدعومة. يسأل التصحيح أولًا عن نوع التغيير: **أخطأتُ في قولي** يستبدل قولك السابق، و**تغيّر الوضع** يسجّل قيمة جديدة من الآن بينما تبقى القديمة صحيحة لفترتها، و**سجّلتَه خطأً** يطلب من Brain إعادة قراءة الرسالة الأصلية وإصلاح السجل. ويُبلغ الحذف عن خطة المحو: مكتمل، أو جزئي إذا تعذّر التحقق من أحد الأسطح، أو محظور بسبب حجز قانوني.

يمكن اختيار وضع لمحادثة جديدة من حقل الكتابة. في CLI: `anda agent run --memory-mode no-store --prompt '…'` أو `--memory-mode off`. تقيّد الوصول التلقائي إلى Brain ولا تجعل المحادثات أو المزودين بلا آثار. كما تُعطّل الوكلاء الفرعيين والإشارات المرجعية وتعديلات cron.

للاحتفاظ بالأسئلة بين المحادثات، استخدم إعداد صندوق الذاكرة أو `anda memory inbox setup`. راجع الإعداد وطبّقه ثم نفّذ `anda restart` صراحةً. تُحفظ الملفات المخصصة وتجاوزات البيئة. يُنشئ الاشتراك سؤالًا أصليًا حقيقيًا عند تغير السجل. في TUI: `/memory inbox` و`/memory answer <number> <text>` و`/memory retry <number>`؛ تُستخدم هوية الحدث والنص المحفوظان عند الإعادة.

اقرأ صندوق الذاكرة باستخدام `anda memory inbox`. اتبع الأمر المعروض `anda memory inbox --cursor <next_cursor>` لقراءة الصفحة التالية. عند استخدام `--json` يكون المؤشر في `result.next_cursor`.

مقارنة MIB وتعلم الأعمال ميزتان متقدمتان منفصلتان. راجع `anda memory evaluate plan --help` في إصدار يتضمن MIB. قد يكون حساب التكلفة غير مكتمل. مقارنة الذاكرة ليست موافقة على تعلم الأعمال ولا دليل تحسن عام.


Anda Brain هو نظام الذاكرة طويلة المدى وراء Anda Bot. إنه ليس قاعدة بيانات متجهة بسيطة أو ملف Markdown ينمو باستمرار؛ إنه دماغ ذاكرة مصمم خصيصاً للوكلاء.

يحول Brain المحادثات والملفات ونتائج الأدوات وسياق القناة إلى محور معرفي (Cognitive Nexus) متنامٍ: الأشخاص والمشاريع والتفضيلات والأحداث والقرارات والجداول الزمنية والعلاقات بينها.

## حلقة ثلاثية المراحل

### التكوين (Formation)

يقوم التكوين بترميز المحادثات المفيدة ونتائج العمل في ذكريات منظمة. لا يقتصر الأمر على التساؤل عما إذا كانت الجملة قد ظهرت؛ بل يسأل من، وأي مشروع، وما هو التفضيل، وما هو القرار، وما هو الحدث، ومتى حدث ذلك.

### الاستدعاء (Recall)

يسمح الاستدعاء بالاستعلام عن مخطط الذاكرة باستخدام اللغة الطبيعية. يشرح الاستدعاء الجيد المهمة الحالية بدلاً من إرجاع شظايا النص المتشابهة وحدها.

### الصيانة (Maintenance)

تعمل الصيانة على دمج الشظايا، ودمج المعلومات المكررة، وتقليل تأثير المعرفة القديمة، والحفاظ على الجداول الزمنية عندما تتغير الحقائق.

## كيف تعلم Anda

لا تحتاج إلى صيانة ملفات الذاكرة يدوياً. النهج الأفضل هو توضيح الحقائق المستقرة والتغييرات والتفضيلات بوضوح.

```text
تذكر: أنا أحب ملاحظات الإصدار القصيرة، ولكن احتفظ بقسم للمخاطر.
تغير مزود النموذج الافتراضي لمساحة العمل هذه من A إلى B.
عندما نذكر أليس، فإننا نعني مصممة فريق الهاتف المحمول.
هل تتذكر خلفية مشروع ترحيل المدفوعات?
```

## ما الذي يجعل الذاكرة جيدة

- السياق: المشروع أو الشخص أو الملف أو القناة أو النطاق الزمني واضح.
- التطور: عندما يتغير التفضيل، اذكر الإصدار القديم والجديد.
- الحدود: يمكن تحديد المعلومات المؤقتة على أنها صالحة للمهمة الحالية فقط.
- التصحيح: عندما تتذكر Anda بشكل غير صحيح، اذكر الإصدار الصحيح مباشرة.

## البيانات المحلية ومزودو النماذج

يتم تخزين بيانات مخطط الذاكرة محلياً في `~/.anda/db` افتراضياً. قد لا يزال مزودو النماذج يشاركون في تكوين الذاكرة، ودعم الاستدعاء، والتلخيص، لذا اختر المزودين ونقاط النهاية (endpoints) وفقاً لاحتياجات الخصوصية الخاصة بك.

لجعل المزود مفضلاً للمهام المتعلقة بالذاكرة، أضف تسمية `brain`:

```yaml
model:
  providers:
    - family: anthropic
      model: "deepseek-v4-pro"
      api_base: "https://api.deepseek.com/anthropic"
      api_key: "YOUR_API_KEY"
      labels: ["primary", "brain"]
```

## مشاركة الذاكرة مع وكلاء آخرين

يمكن لـ Claude Code وCodex وعملاء MCP الآخرين على الجهاز نفسه استخدام ذاكرة Anda عبر MCP. امنح كل وكيل رمزًا خاصًا به؛ وأضف `--write` ليتمكن أيضًا من إخبار الذاكرة بما يجب تذكره:

```bash
anda memory agents add claude-code --write
```

يعرض الأمر الرمز مرة واحدة فقط، مع إعداد Claude Code وCodex:

```bash
claude mcp add --transport http --scope user anda-memory http://127.0.0.1:8042/mcp/memory --header "Authorization: Bearer <token>"
```

```toml
# ~/.codex/config.toml؛ نفّذ export ANDA_MEMORY_TOKEN=<token> قبل تشغيل Codex
[mcp_servers.anda-memory]
url = "http://127.0.0.1:8042/mcp/memory"
bearer_token_env_var = "ANDA_MEMORY_TOKEN"
```

تتصل العملاء الأخرى بنقطة نهاية Streamable HTTP نفسها مع الترويسة `Authorization: Bearer <token>`. تُقدَّم على المسار `/mcp/memory` في عنوان الـ daemon، ولا تقبل إلا اسم مضيف حلقة استرجاع (`localhost` أو `127.0.0.1` أو `::1`)، وترفض الطلبات القادمة من صفحات الويب؛ ومع ذلك يحتاج كل طلب إلى رمز، ويتصل العميل الموجود على جهاز آخر عبر نفق.

| الأداة | الصلاحية | ما تفعله |
| --- | --- | --- |
| `recall_memory` | كل الرموز | تجيب عن سؤال من الذاكرة باستخدام نموذج ذاكرة Anda، بعد انتظار قصير لملاحظات الوكيل نفسه التي ما زالت قيد المعالجة |
| `search_memory` | كل الرموز | تبحث عن الكيانات بالاسم دون استدعاء نموذج |
| `read_memory_entity` | كل الرموز | تسرد ادعاءات كيان ما، الأحدث أولًا، مع الاعتقاد الحالي لدى Anda واقتباسات من مصادرها، دون استدعاء نموذج |
| `remember` | `--write` | تسجّل ملاحظة بكلمات الوكيل نفسه وترسلها إلى Formation؛ ويجعل `idempotency_key` إعادة المحاولة آمنة |
| `memory_note_status` | `--write` | تُبلغ ما إذا كانت الملاحظة قد عولجت |

الملاحظة تصريح من الوكيل، تُنسب إليه بصفته مشاركًا مسمّى (مثل "Claude Code")، ولا تُنسب إليك أبدًا ولا إلى Anda نفسها. تُحفظ في محادثة خاصة بها مصدرها `agent:claude-code`، وتعرض مساحة **الذاكرة** ما كوّنته Formation منها مع هذا المصدر، جاهزًا للتصحيح أو إيقاف الاستخدام أو الحذف مثل أي سجل آخر.

يقرأ الرمز ما تقرؤه Anda، لذا لا تمنحه إلا لوكيل تثق به في ذاكرتك، وتذكّر أن ما يقرؤه يصل إلى مزوّد النماذج الخاص به. تعمل Recall وFormation على نماذج ذاكرة Anda وتُحتسب تكلفتها هناك. يسرد `anda memory agents` التصاريح وآخر استخدام لكل منها، ويوقف `anda memory agents revoke <id|client>` الرمز فورًا. تبقى الرموز صالحة 90 يومًا ما لم يحدد `--days` مدة أخرى (حتى 3650). لا تحتفظ Anda إلا بملخّص لكل رمز، لذا لا يمكن عرض الرمز المفقود مرة أخرى: ألغِه وأنشئ رمزًا جديدًا. وأثناء تحضير Anda لتحديث، تُعيد نقطة النهاية 503 حتى يكتمل.

## بيئة أصلية اختيارية

اضبط `brain.runtime_config` على ملف JSON/YAML موثوق بمسار نسبي إلى دليل الإعدادات؛ تكون الأولوية لـ `BRAIN_RUNTIME_CONFIG`. أعد التشغيل لتثبيت الروابط قبل تحميل Space. يحتفظ صندوق Brain في المتصفح وأوامر `/brain inbox` و`/brain status` و`/brain formation <id>` بالهوية الموثقة. القراءة لا تمنح إذن التنفيذ؛ أعد إرسال الرد بالحدث والنص نفسيهما. إيصال Recall يثبت التسليم فقط، وقبول Formation لا يعني اكتماله. ميزة `learning` مستقلة عن `mib`؛ الدلالات وutility وtrust والتعلم التلقائي تتطلب إعداداً أصلياً صريحاً. وسائل IM الحالية ليست محولات إجراءات تلقائية. وضع MIB persistent لا يدّعي تعلم normal/ungated أو اكتمال حساب التكاليف. كل نافذة Formation نيةٌ مرصودة بإيصال دائم، لذا يعيد الإرسال المنقطع الإيصال نفسه بدلًا من معالجة النافذة مرتين. ينتظر `recall_memory` أولًا لفترة قصيرة نوافذ المحادثة نفسها المعلّقة ويذكر ما يزال قيد المعالجة. ويعيد `brain_attention` أيضًا الالتزامات المستحقة وwatches التي انطلقت منذ آخر اطلاع، ويسجّل `brain_feedback` تقرير المساعد الذاتي كدليل منسوب لا كتقييم.

```yaml
brain:
  runtime_config: brain-runtime.yaml
```

تظل الرموز القديمة صالحة دون إعادة تصديرها؛ تحتفظ الطلبات بالهوية الأصلية، ويقبل Brain المضمّن رمزًا بلا جمهور مع التحقق من توقيعه وصلاحيته.
