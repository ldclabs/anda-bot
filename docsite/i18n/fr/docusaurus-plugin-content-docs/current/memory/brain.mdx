# Cerveau de mémoire Brain

## Commencez par une conversation

Lancez `anda memory guide` pour une introduction hors ligne. La mémoire quotidienne ne nécessite aucune configuration Brain ou MIB. Énoncez une préférence stable, attendez le traitement puis ouvrez une nouvelle conversation avec `/new` pour la vérifier. Une réponse « mémorisé » ne prouve pas son enregistrement.

`anda memory` et `/memory` dans la TUI consultent l’état sans modèle. L’espace **Mémoire** du navigateur affiche les enregistrements, sources vérifiées et activités ; le graphe reste dans **Explorer les relations**. La recherche peut appeler un modèle et ne se relance pas automatiquement.

Vérifiez l’aperçu avant de corriger, désactiver ou supprimer. Désactiver conserve les enregistrements archivés ; supprimer purge l’ensemble natif affiché. Les exclusions de sources survivent au redémarrage et les Notes de traitement sont effacées. Conversations, fichiers, journaux, sauvegardes et contexte déjà livré restent. Les périmètres incomplets ou non pris en charge sont refusés. Une correction demande d’abord de quel changement il s’agit : **Je me suis trompé** remplace votre affirmation précédente, **La situation a changé** enregistre une nouvelle valeur à partir de maintenant tandis que l’ancienne reste vraie pour sa période, et **Tu l’as mal enregistré** demande à Brain de relire le message d’origine et de réparer l’enregistrement. La suppression indique son plan d’effacement : terminé, partiel si une surface n’a pas pu être vérifiée, ou bloqué par une conservation légale.

Le composeur permet de choisir un mode pour une nouvelle conversation. En CLI : `anda agent run --memory-mode no-store --prompt '…'` ou `--memory-mode off`. Ces modes limitent l’accès automatique à Brain/Notes, sans rendre les conversations ou fournisseurs incognito. Sous-agents, favoris et modifications cron sont aussi bloqués.

Pour garder des questions entre conversations, utilisez la configuration de la boîte mémoire ou `anda memory inbox setup`. Vérifiez, appliquez puis lancez explicitement `anda restart`. Fichiers personnalisés et variables d’environnement sont préservés. Un abonnement produit un élément natif réel lors d’un changement. TUI : `/memory inbox`, `/memory answer <numéro> <texte>`, `/memory retry <numéro>` ; la relance conserve l’événement et le texte.

Consultez la boîte avec `anda memory inbox`. Suivez la commande affichée `anda memory inbox --cursor <next_cursor>` pour lire la page suivante. Avec `--json`, le curseur se trouve dans `result.next_cursor`.

Comparaison MIB et apprentissage métier sont deux fonctions avancées distinctes. Consultez `anda memory evaluate plan --help` dans une version avec MIB. Les coûts peuvent être incomplets. Une comparaison mémoire n’approuve pas l’apprentissage métier et ne prouve pas une amélioration générale.


Anda Brain est le système de mémoire à long terme sous-jacent à Anda Bot. Ce n'est pas une simple base de données vectorielle ni un fichier Markdown à croissance infinie ; c'est un cerveau de mémoire spécialement conçu pour les agents IA.

Le Brain transforme les conversations, les fichiers, les résultats d'outils et le contexte des canaux en un Cognitive Nexus (nouveau cognitif) en développement constant : personnes, projets, préférences, événements, décisions, chronologies et les relations qui les lient.

## Boucle en trois phases

### Formation

La Formation encode les conversations et les résultats de travail utiles en mémoires structurées. Elle ne se contente pas de vérifier la présence d'une phrase ; elle détermine qui, quel projet, quelle préférence, quelle décision, quel événement, et quand cela s'est produit.

### Rappel (Recall)

Le Rappel permet de requêter le graphe de mémoire en langage naturel. Un bon rappel apporte du contexte à la tâche en cours au lieu de simplement retourner des fragments de texte similaires.

### Maintenance

La Maintenance consolide les fragments, fusionne les informations redondantes, atténue l'influence des connaissances obsolètes et préserve les chronologies lorsque les faits évoluent.

## Comment enseigner à Anda

Vous n'avez pas besoin de gérer manuellement des fichiers de mémoire. La meilleure approche consiste à énoncer clairement les faits stables, les changements et vos préférences.

```text
Remember: I like short release notes, but keep a risk section. (Rappelle-toi : j'aime les notes de version courtes, mais conserve une section sur les risques.)
Le fournisseur de modèles par défaut pour cet espace de travail est passé de A à B.
Quand nous parlons d'Alice, nous faisons référence à la designer de l'équipe mobile.
Te souviens-tu du contexte du projet de migration des paiements ?
```

## Ce qui fait une bonne mémoire

- Le contexte : le projet, la personne, le fichier, le canal ou la plage temporelle sont clairs.
- L'évolution : lorsqu'une préférence change, indiquez l'ancienne et la nouvelle version.
- Les limites : les informations temporaires peuvent être marquées comme valides uniquement pour la tâche en cours.
- La correction : si Anda se souvient de manière erronée, énoncez directement la version correcte.

## Données locales et fournisseurs de modèles

Les données du graphe de mémoire sont stockées localement dans `~/.anda/db` par défaut. Les fournisseurs de modèles peuvent toujours participer à la formation de la mémoire, au support du rappel et à la synthèse ; choisissez donc vos fournisseurs et points de terminaison en fonction de vos exigences de confidentialité.

Pour définir un fournisseur comme prioritaire pour les tâches liées à la mémoire, ajoutez le label `brain` :

```yaml
model:
  providers:
    - family: anthropic
      model: "deepseek-v4-pro"
      api_base: "https://api.deepseek.com/anthropic"
      api_key: "VOTRE_CLE_API"
      labels: ["primary", "brain"]
```

## Environnement natif facultatif

Définissez `brain.runtime_config` vers un fichier JSON/YAML de confiance, relatif au dossier de configuration ; `BRAIN_RUNTIME_CONFIG` est prioritaire. Redémarrez pour installer les liaisons avant le chargement du Space. La boîte Brain du navigateur et `/brain inbox`, `/brain status`, `/brain formation <id>` dans le terminal conservent l’identité authentifiée. La lecture n’autorise aucune exécution ; réessayez une réponse avec le même événement et texte. Un reçu Recall prouve seulement la livraison ; accepter Formation ne signifie pas le terminer. La fonctionnalité `learning` est indépendante de `mib` ; sémantique, utility, trust et apprentissage automatique exigent une configuration native explicite. Les transports IM actuels ne sont pas des adaptateurs d’action automatique. Le mode MIB persistent ne garantit ni apprentissage normal/ungated ni coûts complets. Chaque fenêtre Formation est une intention observée avec un reçu durable : un envoi interrompu rejoue le même reçu au lieu de traiter la fenêtre deux fois. `recall_memory` attend d’abord brièvement les fenêtres en attente de la conversation et indique celles encore en cours. `brain_attention` renvoie aussi les engagements échus et les watches déclenchés depuis la dernière consultation, et `brain_feedback` enregistre le compte rendu de l’assistant comme preuve attribuée, jamais comme une note.

```yaml
brain:
  runtime_config: brain-runtime.yaml
```

Les anciens jetons restent valables sans réexportation : les requêtes conservent l’identité d’origine et le Brain intégré accepte un jeton sans audience, tout en vérifiant sa signature et son expiration.
