# Конфигурация среды выполнения

По умолчанию Anda сохраняет параметры среды выполнения в каталоге `~/.anda`. Основным файлом конфигурации является `~/.anda/config.yaml`, создаваемый автоматически при первом запуске программы. Дополнительные параметры серверов MCP задаются в файле `~/.anda/mcp.json`.

## Провайдеры моделей

Блок настроек каждого активного провайдера должен включать параметры `family` (семейство моделей), `model` (конкретная модель) и `api_base` (адрес API). Ключ авторизации `api_key` можно прописать в файле конфигурации или оставить пустым, если он передается через переменную окружения.

```yaml
model:
  active: "deepseek-v4-pro"
  providers:
    - family: anthropic
      model: "deepseek-v4-pro"
      api_base: "https://api.deepseek.com/anthropic"
      api_key: "ВАШ_API_KEY"
      labels: ["pro", "brain"]
      disabled: false
```

Поддерживаемые переменные окружения для API-ключей моделей:

```text
OPENAI_API_KEY
ANTHROPIC_API_KEY
GEMINI_API_KEY
GOOGLE_API_KEY
DEEPSEEK_API_KEY
MINIMAX_API_KEY
MIMO_API_KEY
MOONSHOT_API_KEY
KIMI_API_KEY
BIGMODEL_API_KEY
GLM_API_KEY
```

## Основные глобальные параметры

| Параметр | Назначение |
| --- | --- |
| `addr` | Локальный адрес шлюза (gateway), по умолчанию `127.0.0.1:8042`. |
| `sandbox` | При значении `true` выполнение консольных команд изолируется в `~/.anda/sandbox`. |
| `https_proxy` | Прокси-сервер для запросов к моделям и внешним каналам связи. |
| `model` | Настройки провайдеров моделей для работы агента и памяти Brain. |
| `transcription` | Провайдер для распознавания голосового ввода и аудиофайлов. |
| `tts` | Провайдер для синтеза речи (голосового озвучивания ответов). |
| `channels` | Настройки интеграции с Telegram, WeChat, Discord, Lark/Feishu и др. |

## Серверы MCP

Anda Bot может подключаться к серверам MCP через стандартные потоки ввода-вывода (stdio) дочерних процессов или по протоколу HTTP. Пропишите переносимые настройки серверов в файле `~/.anda/mcp.json` и выполните `anda mcp reload` (или перезапустите демона). В качестве корневого ключа поддерживаются как `mcpServers`, так и `servers`, что позволяет без изменений копировать настройки из других MCP-совместимых приложений.

```json
{
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "$ANDA_WORKSPACE"]
    },
    "remote": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${secret:MCP_REMOTE_TOKEN}"
      }
    }
  }
}
```

Подключенные инструменты удаленных MCP-серверов регистрируются в Anda под именами вида `mcp_<server_id>_<remote_tool>`. В строках конфигурации поддерживается подстановка переменных окружения вида `$VAR` и `${VAR}`, а также `${VAR:-default}` для переменной, которая может быть не задана, и `${secret:NAME}` для секрета (см. раздел «Секреты» ниже). По умолчанию доступны встроенные переменные `ANDA_HOME` и `ANDA_WORKSPACE`. Для stdio-серверов параметр `command` запускается напрямую без создания оболочки shell; при отсутствии параметра `cwd` рабочей директорией становится первое рабочее пространство Anda. Если параметр `type` не указан, Anda автоматически определит его как `stdio` (при наличии `command`) или `http` (при наличии `url`).

Каждая запись загружается отдельно, и MCP никогда не мешает запуску daemon: непригодная запись (не задана переменная окружения, неподдерживаемый `type`, например устаревший `sse`, повторяющийся id) пропускается с предупреждением в журнале daemon, а остальные серверы загружаются как обычно. Серверы подключаются в фоне после запуска daemon, поэтому медленная конечная точка или первая загрузка `npx -y` не задерживают его; чтобы инструменты сервера были обнаружены до того, как daemon сообщит о готовности, добавьте в запись `"startup": "eager"`. Stdio-серверы получают тот же расширенный `PATH`, что и инструмент shell, поэтому `npx`, `uvx` и команды Homebrew находятся, даже когда daemon запущен как служба входа в систему; такая служба не видит переменные, экспортированные в профиле вашей оболочки, поэтому для ссылок `${VAR}` переменная должна быть задана в окружении самого daemon.

Запись может также настраивать, как работает её сервер. `timeouts` задаются в секундах, каждый от 1 до 86400: `setup_secs` на подключение (по умолчанию 90), `list_secs` на получение списка инструментов (30), `request_secs` на один запрос (180) и `call_secs` на весь вызов инструмента (600). `concurrency` определяет, какие инструменты могут работать одновременно: `serial` (по умолчанию), `read_only_parallel` (помеченные сервером как только читающие) или `parallel`. `limits.output_text_bytes` — текст, который агент получает из одного результата, от 256 до 1048576 (по умолчанию 32768). `lifecycle` определяет, как согласуется версия протокола (`auto`, `discover` или `initialize`), а `tasks` (`{"max_wait_secs": 900}`) позволяет долгому инструменту вернуть задачу, которую Anda опрашивает до завершения. Локальный сервер получает всё окружение демона, если не указано `"inherit_env": false`: тогда он получает только необходимое платформе (`PATH`, `HOME`, `TMPDIR` и подобные) и собственный `env`, и никакие другие секреты из окружения демона к нему не попадают. `resources` и `elicitation` включены, если не указано `false`: они определяют, могут ли агент и приложения получать список [ресурсов](#ресурсы-и-запросы-ввода) сервера и читать их и может ли сервер [запрашивать у вас ввод](#ресурсы-и-запросы-ввода), пока работает один из его инструментов; `timeouts.elicitation_secs` (300) — сколько он ждёт вашего ответа. Эти настройки меняете вы — в `mcp.json`, на странице MCP или командой `anda mcp options`, а не инструменты агента.

Агент также может динамически подключать серверы во время работы с помощью функции `add_mcp_server`. Укажите `persist: false` для работы сервера только в рамках текущей сессии демона, или `persist: true` для записи конфигурации в файл `~/.anda/mcp.json` с целью автоматического запуска при последующих перезапусках. Параметры функции соответствуют полям в файле `mcp.json`: `type`, `command`, `args`, `env`, `cwd`, `url`, `headers`, `enabled`, `include` и `exclude`, а также специфические для инструментов поля `id` и `persist`. `manage_mcp_server` позволяет агенту просматривать серверы с их состоянием и последней ошибкой и переподключать сервер; включение, отключение и удаление сервера, а также выход из его учётной записи требуют вашего подтверждения.

### Управление серверами с помощью `anda mcp`

```bash
anda mcp list                                         # состояние, инструменты и последняя ошибка каждого сервера
anda mcp get github                                   # один сервер и его инструменты
anda mcp add context7 -- npx -y @upstash/context7-mcp
anda mcp add docs --url https://docs.example.com/mcp --header 'Authorization: Bearer ${DOCS_TOKEN}'
anda mcp add-json notes '{"type":"http","url":"https://notes.example.com/mcp"}'
anda mcp login linear --url https://mcp.linear.app/mcp  # вход по OAuth; --no-browser печатает адрес
anda mcp tool github delete_repository --hide         # скрыть инструмент от агента
anda mcp secret set DOCS_TOKEN                        # также: secret list, secret unset
anda mcp disable context7                             # также: enable, remove, reconnect, logout, reload
anda mcp options github --call-timeout 900            # дополнительные настройки; `default` сбрасывает
anda mcp import --dry-run                             # серверы, настроенные в других приложениях
anda mcp import github notes=work-notes --from cursor # импортировать их; без имён — все новые
anda mcp events github                                # события, о которых сообщает сервер
anda mcp triggers                                     # автоматизации по событиям; также: add, get, update, pause, resume, delete
```

Когда демон запущен, каждая команда выполняется через него, и изменение применяется сразу: сервер, у которого изменились параметры подключения, перезапускается, а сервер, изменение которого подключения не касается (например, поле, которое Anda не читает), продолжает работать. К серверам с ошибкой подключения демон переподключается в фоне с интервалом от 30 секунд до 30 минут, а причина ошибки сохраняется для `list`. Без демона команды `add`, `add-json`, `remove`, `enable`, `disable`, `tool`, `approval`, `external-users`, `secret`, `options`, `import` и `logout` изменяют файлы напрямую, и изменения вступают в силу при запуске демона. `list` также показывает пропущенные записи и причину пропуска, а `--json` выводит любой результат в формате JSON. Изменения сохраняют поля, которые Anda не читает, ссылки `${VAR}` и корневой ключ файла; `remove` также удаляет сохранённые данные входа сервера, если не указан `--keep-credentials`. Anda не отслеживает изменения `mcp.json`: после ручного редактирования выполните `anda mcp reload`. Источник каждого сервера, его последняя ошибка, проверенные вами определения инструментов и инструкции и число вызовов его инструментов хранятся в `~/.anda/mcp_state.json`.

### Страница MCP

Anda Desktop (MCP на боковой панели) и панель расширения (`#mcp`) управляют одними и теми же серверами. Страница перечисляет серверы с их состоянием и показывает для каждого последнюю ошибку, использование и инструкции; его инструменты с политикой подтверждения каждого, подсказками сервера и тем, что изменилось с вашей проверки; вход; используемые им секреты; и его запись со скрытыми секретами. Добавление принимает URL с заголовками, команду с переменными окружения или конфигурацию, вставленную из другого приложения. Перед любым запуском показывается полная командная строка, подключение проверяется, и по умолчанию значения заголовков, токены и ключи сохраняются как секреты, так что в `mcp.json` остаются только ссылки `${secret:...}`. Сервер, которому нужен OAuth, открывает страницу входа в вашем браузере.

Меню «Добавить» также импортирует серверы из других приложений и открывает MCP Registry (см. ниже), а вкладка «Конфигурация» изменяет дополнительные настройки.

В Anda Desktop ссылка вида `anda://mcp/install?name=<id>&config=<base64url JSON>` открывает диалог добавления с этой конфигурацией и предупреждением проверить, что она запускает. Ничего не сохраняется, пока вы не добавите сервер, а ссылка не может изменить существующий сервер.

### Импорт из других приложений

`anda mcp import` и «Импорт из других приложений» на странице MCP читают настройки MCP приложений Claude Desktop, Claude Code (`~/.claude.json`), Cursor, VS Code (и CLI GitHub Copilot, `~/.copilot/mcp-config.json`), Windsurf и Codex (`~/.codex/config.toml`), а также файлы проектов (`.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json`) в проектах, известных Claude Code, и в текущем каталоге (для CLI) или рабочем каталоге демона. Эти файлы только читаются и никогда не изменяются.

```bash
anda mcp import --dry-run                    # чем станет каждый сервер
anda mcp import                              # все серверы, новые для Anda
anda mcp import github notes=work-notes      # только названные; NAME=ID переименовывает
anda mcp import --from cursor --keep-plaintext
```

Для каждого сервера показано, что сделает импорт: новый; переименованный, если его имя занято другим сервером; уже есть в Anda; тот же сервер, что и один из перечисленных выше; или сервер, который нельзя импортировать (например, SSE-сервер), с причиной. При импорте запись переводится в формат Anda: `${env:NAME}`, `${userHome}` и `${workspaceFolder}` из VS Code подставляются, а `serverUrl` из Windsurf, списки инструментов Copilot и таблицы Codex распознаются. Значения заголовков, токены и ключи переносятся в секреты, если не указан `--keep-plaintext`. `${input:...}` из VS Code и переменная окружения, которой нет у демона, становятся секретами, которые нужно задать: CLI и страница запрашивают их, а сервер, чей секрет ещё не задан, ждёт его. Импортированные локальные серверы получают `"inherit_env": false`. То, что не переносится (например, `envFile` или список автоматически одобренных инструментов), указывается рядом с сервером.

### MCP Registry

«Открыть MCP Registry» на странице MCP ищет в официальном [MCP Registry](https://registry.modelcontextprotocol.io). Запрос выполняет демон со своими настройками прокси. Сервер, опубликованный с удалённой точкой подключения, по умолчанию устанавливается как эта точка, поскольку на вашем компьютере ничего не запускается; вместо неё можно выбрать один из его пакетов npm, PyPI, OCI (Docker) или NuGet, который запускается как локальная команда с `"inherit_env": false`. Форма установки запрашивает объявленные сервером переменные URL, заголовки, переменные окружения и аргументы; значение, помеченное как секрет, попадает в хранилище секретов. Перед установкой сервер можно проверить. Registry показывает только то, что сервер опубликован, а не то, что он безопасен: пока вы не разрешите его инструменты, они спрашивают перед запуском.

### Секреты

`${secret:NAME}` в заголовке, переменной окружения, аргументе или URL раскрывается в секрет, хранящийся в `~/.anda/mcp_secrets.json`, который может читать только ваш пользователь, поэтому в `mcp.json` нет токенов, и его можно передавать или копировать как есть. В именах допустимы буквы, цифры и `_`, и один секрет может использоваться несколькими серверами.

```bash
anda mcp secret set GITHUB_PAT              # читает значение без отображения
gh auth token | anda mcp secret set GITHUB_PAT
anda mcp secret list                        # имена, заданы ли они и какие серверы их используют
anda mcp secret unset GITHUB_PAT
```

Ни CLI, ни страница MCP, ни API больше не показывают значение: чтобы изменить его, задайте новое. Сервер, у которого не задан секрет, пропускается с диагностикой, называющей этот секрет, и запускается, как только вы его зададите; новое значение перезапускает серверы, которые его используют. При удалении сервера удаляются и секреты, которые использовал только он, если не указан `--keep-credentials`.

### Подтверждение вызовов инструментов MCP

Каждый вызов инструмента MCP агентом проходит проверку подтверждения, как и команды shell. Решение принимает политика `approval` сервера — для всех его инструментов или для одного:

| Политика | Когда агент сначала спрашивает |
| --- | --- |
| `auto` (по умолчанию) | Если у сеанса нет полного доступа. Инструменты, которые сервер помечает как только для чтения, выполняются без вопроса, пока их определение не изменилось. |
| `ask` | Всегда, даже при полном доступе. |
| `allow` | Никогда, пока определение инструмента не изменилось. |

```json
"github": {
  "type": "http",
  "url": "https://api.githubcopilot.com/mcp/",
  "approval": { "default": "allow", "tools": { "merge_pull_request": "ask" } }
}
```

```bash
anda mcp approval github allow                              # все инструменты сервера
anda mcp approval github ask --tool merge_pull_request      # один инструмент
anda mcp approval github inherit --tool merge_pull_request  # вернуться к политике сервера
```

Политика читается только при вызове инструмента, поэтому её изменение никогда не переподключает сервер. Задачи по расписанию и цели выполняются с полным доступом, поэтому инструменты `auto` в них тоже выполняются. Там, где на запрос подтверждения некому ответить, например в чате IM или в задаче по расписанию, встретившей инструмент `ask`, вызов не выполняется, а агент узнаёт, как вы можете его разрешить.

Карточка подтверждения инструмента MCP также предлагает «Разрешать всегда» (клавиша `a` в TUI): вызов подтверждается, а для инструмента устанавливается `allow`.

Anda сохраняет определение каждого инструмента в том виде, в каком сервер впервые его предоставил. Если позже сервер меняет описание или схему инструмента либо добавляет инструмент, этот инструмент теряет то, что было разрешено его прежнему определению: агент спрашивает о нём даже при `allow`, пока вы не подтвердите один его вызов или не примете его командой `anda mcp review github` (все инструменты) или `anda mcp review github <tool>`. `anda mcp diff github <tool>` показывает, что изменилось, а `anda mcp get github` отмечает инструменты, требующие проверки. Инструкции, которые сервер даёт модели, сохраняются так же: когда они меняются, `anda mcp get` сообщает об этом, а страница MCP показывает обе версии, пока `anda mcp review github` их не примет.

Запросы внешних пользователей IM могут вызывать инструменты сервера, только если сервер это разрешает (`"allow_external_users": true` или `anda mcp external-users github on`), и никогда — инструмент, требующий подтверждения: внешний пользователь не может подтверждать за вас.

Навыки, написанные для других агентов, могут называть инструменты MCP в виде `mcp__<server>__<tool>`, и Anda сопоставляет эти имена с теми же инструментами. Шаблон вида `mcp__github__*` не разрешается: перечислите каждый инструмент.

### Автоматизации по событиям

Серверы с поддержкой расширения MCP Events сообщают о событиях, например о новой issue или новом комментарии. Когда приходит событие, автоматизация запускает агента с вашими инструкциями. Создайте её на вкладке «События» сервера на странице MCP, командой `anda mcp triggers add` или попросив агента: его `create_event_trigger` сначала запрашивает ваше одобрение.

```bash
anda mcp events github                         # типы событий, способ доставки и аргументы
anda mcp triggers add github issue.opened --args '{"repo":"owner/name"}' \
    --instructions "Добавь метку к каждой новой issue и кратко её опиши" --batch-window 60
anda mcp triggers get 3                        # состояние, последние запуски и события
anda mcp triggers update 3 --instructions "Поставь метку и назначь ответственного"  # неуказанное остаётся
anda mcp triggers pause 3                      # также: resume, delete
```

- **Куда идут результаты.** Автоматизация, созданная на странице MCP или через CLI, отвечает в вашем разговоре, который продолжают последующие запуски; созданная агентом отвечает там, где её попросили создать: в том разговоре или IM-чате.
- **Группировка и лимиты.** События, пришедшие в пределах окна группировки (по умолчанию 30 секунд, не больше часа), обрабатываются за один запуск, не более 20 событий. Автоматизация сама приостанавливается, если превысила бы часовой лимит запусков (`max_runs_per_hour`, по умолчанию 12) — это обрывает и петлю обратной связи, например ответ на issue, который возвращается новым событием, — а также после пяти неудачных запусков подряд. Возобновите её, когда будете готовы.
- **Доверие.** Данные событий приходят от сервера, и им нельзя доверять: модель получает их как данные, а не как инструкции, и они не записываются как ваши слова. У этих запусков нет полного доступа, как у задач по расписанию: доступны инструменты только для чтения и инструменты с настройкой `allow`, а всё, что требует одобрения (инструмент записи в режиме `auto`, рискованная команда shell), отклоняется.
- **Изменения и уведомления.** Изменить автоматизацию можно на вкладке «События» или командой `anda mcp triggers update`; изменение события, аргументов или способа доставки заново подписывает её с текущего момента. Диалог также называет инструменты сервера, в которых ей будет отказано. Когда автоматизация сама встаёт на паузу, её серверу нужен вход или сервер завершает подписку, Anda сообщает вам об этом коротким сообщением там, куда приходят её ответы.
- **Память.** То, что приносит запуск, приписывается серверу и событию (`mcp:<server>/<event>`) как внешнему источнику — так же, как слова внешнего отправителя IM, — поэтому Formation никогда не записывает это как ваше.
- **Доставка.** Anda держит открытым push-поток или опрашивает сервер — как позволяет тип события — и запоминает достигнутую позицию, поэтому события, пришедшие, пока daemon был остановлен, воспроизводятся, если сервер это поддерживает; уже обработанное событие не запускается повторно. Если сервер сообщает о потерянных событиях, автоматизация это показывает. Автоматизация, чей сервер отключён, удалён или не работает, ждёт; если серверу нужен вход, она об этом сообщает; в обоих случаях работа продолжается, когда сервер возвращается.
- **Webhook через dMsg.** Некоторые серверы доставляют события только через webhook, а Anda не слушает публичные порты. Отметьте запись dMsg параметром `"events": {"webhook_ingress": true}`: для каждой такой автоматизации Anda создаёт там конечную точку, подписывает на неё сервер и продлевает подписку до её истечения, а dMsg пересылает проверенные им доставки. Без приёмника автоматизация ждёт в состоянии `needs_ingress`.

```json
{
  "mcpServers": {
    "dmsg": { "command": "dmsg", "args": ["mcp"], "events": { "webhook_ingress": true } }
  }
}
```

Автоматизации, полученные события и их запуски хранятся в базе данных daemon; секрет подписи конечной точки хранится в хранилище секретов MCP.

### Ресурсы и запросы ввода

Серверы могут предлагать ресурсы — файлы, записи и другой контекст по URI. Агент получает их список и читает их инструментом `mcp_resources` (`list` — без сервера для всех подключённых, `templates` — шаблоны URI для заполнения, `read` — чтение); короткий текст возвращается сразу, длинное или двоичное содержимое — вложением. В Anda Desktop и расширении в меню + поля ввода есть пункт «Ресурс MCP»: он показывает ресурсы подключённых серверов и прикрепляет выбранный к вашему сообщению. Чтение ничего не меняет, поэтому подчиняется политике одобрения сервера как проверенный инструмент только для чтения: выполняется без вопросов, если сервер не настроен на `ask` и сеанс не требует одобрять всё, а внешние пользователи IM получают доступ только к серверам, которые это разрешают. То, что возвращает сервер, недоверенно, как и результат инструмента.

Сервер также может запросить у вас ввод, пока работает один из его инструментов (MCP elicitation). Anda показывает запрос над полем ввода в том разговоре, для которого выполняется вызов: форма превращается в карточку на каждое поле с проверкой ответа (число в диапазоне, адрес почты, один из вариантов), а запрос открыть страницу — в карточку со ссылкой, которая открывается при выборе Open the page. Decline сообщает серверу, что вы не ответите; ответ в чате вместо карточки или истечение срока сервера (`timeouts.elicitation_secs`, по умолчанию 300 секунд) отменяет запрос. Там, где ответить некому — в автоматизации, задаче по расписанию или IM-чате, — запрос отменяется сразу. Ответ уходит серверу, поэтому никогда не вводите в такой карточке пароли, ключи или платёжные данные.

Обе функции включены по умолчанию. Чтобы выключить одну, укажите в записи `"resources": false` или `"elicitation": false` либо выполните `anda mcp options <id> --resources off` (или `--elicitation off`).

## Структура локального каталога

```text
~/.anda/
  config.yaml
  mcp.json
  mcp_secrets.json
  mcp_state.json
  anda-daemon.pid
  channels/
  credentials/ # локальное зашифрованное хранилище учетных данных доверенных пользователей
  db/
  keys/ # экспортированные файлы ключей или резервные ключи Secret Service
  logs/
  bundled-skills/
  sandbox/
  skills/
  skills-manifest.json
  skill-backups/
  skill-trash/
  workspace/
```

| Директория | Описание содержимого |
| --- | --- |
| `credentials/` | Локальное зашифрованное хранилище учетных данных. Приватные ключи доверенных пользователей хранятся здесь в виде зашифрованных COSE-ключей. |
| `db/` | Базы данных локальной памяти, переписок, состояния каналов, планировщика cron, объектов и др. |
| `keys/` | Файлы ключей подписи, экспортированные вручную или резервные файлы Linux Secret Service. Приватные ключи демона и владельца по умолчанию сохраняются в защищенном хранилище учетных данных ОС, если оно доступно. |
| `logs/` | Файлы журналов работы демона и утилиты CLI. |
| `channels/` | Файлы состояния каналов связи. |
| `bundled-skills/` | Встроенные навыки (Skills), поставляемые и обновляемые вместе с релизами Anda. |
| `sandbox/` | Директория изоляции при включенном режиме песочницы (sandbox) для консольных команд. |
| `skills/` | Пользовательские навыки, созданные, скопированные или отредактированные вручную. |
| `skills-manifest.json` | Навыки, отключённые в панели управления. Если файл не удаётся разобрать, об ошибке сообщается, а файл остаётся без изменений. |
| `skill-backups/` | Копии `SKILL.md` личного навыка с временными метками, сохраняемые перед каждым обновлением. |
| `skill-trash/` | Корзина для временного хранения удаленных пользовательских навыков перед их окончательным стиранием. |
| `workspace/` | Рабочее пространство по умолчанию для инструментов работы с файлами и консолью. |

## Границы конфиденциальности

Локальное состояние Anda, граф памяти Brain, переписки, состояние каналов связи, планировщика задач cron, файлы логов и рабочее пространство по умолчанию хранятся локально на вашем компьютере. Приватные ключи демона и владельца по умолчанию записываются в защищенное системное хранилище ОС, в то время как приватные ключи доверенных пользователей сохраняются в локальном зашифрованном хранилище учетных данных в `~/.anda/credentials/`. Экспортированные вручную файлы ключей и резервные файлы Linux Secret Service могут находиться в каталоге `~/.anda/keys/`.

На Linux при отсутствии или блокировке службы Secret Service Anda переходит в режим использования файлов ключей демона/владельца в `~/.anda/keys/` и выводит предупреждение в терминал и лог-файл. Приватные ключи доверенных пользователей остаются зашифрованными в локальном хранилище учетных данных до тех пор, пока может быть загружен секрет демона. Для работы с Secret Service для учетных записей демона/владельца запустите и разблокируйте провайдера в пользовательской D-Bus сессии (например, выполнив `gnome-keyring-daemon --start --components=secrets`), убедитесь, что переменная `DBUS_SESSION_BUS_ADDRESS` установлена для процесса Anda, и перезапустите программу. Пользователи KDE могут аналогично разблокировать хранилище KWallet.

Тем не менее, внешние провайдеры языковых моделей по-прежнему получают промпты, резюме результатов работы инструментов и запросы на формирование/вызов памяти. Выбирайте надежных провайдеров, используйте частные прокси-серверы и защищенные адреса в соответствии с вашими требованиями к конфиденциальности.

:::tip
Используйте параметр `anda --home /путь/к/.anda` для изоляции данных и настроек разных пользователей, проектов или тестовых сценариев.
:::

## Brain runtime

Укажите доверенный JSON/YAML в `brain.runtime_config` относительно каталога конфигурации; `BRAIN_RUNTIME_CONFIG` имеет приоритет. Перезапустите сервис для установки связей до загрузки Space. Входящие Brain в браузере и команды `/brain inbox`, `/brain status`, `/brain formation <id>` сохраняют подтверждённую личность. Чтение не разрешает выполнение; повторяйте ответ с тем же событием и текстом. Квитанция Recall подтверждает только доставку, принятие Formation не означает завершение. Функция `learning` независима от `mib`; семантика, utility, trust и автоматическое обучение требуют явной нативной конфигурации. Текущие IM-транспорты не являются автоматическими адаптерами действий. MIB persistent не заявляет обучение normal/ungated или полный учёт затрат.

```yaml
brain:
  runtime_config: null
```

Можно также подключить подходящую подписку ChatGPT Plus / Pro без ключа API:

```bash
anda auth login chatgpt
anda auth accounts
anda auth models <profile-id>
anda auth use <profile-id> <model-slug>
anda auth logout <profile-id>
```

В Anda Desktop откройте **Настройки → Настройки агента → Модели**. В расширении откройте раздел **Модели** на странице конфигурации или в настройках боковой панели. Нажмите **Continue with ChatGPT**, завершите авторизацию в браузере и выберите **Использовать выбранную модель**. В TUI нажмите **Ctrl+G**. CLI/TUI выбирает первую доступную модель; в CLI можно указать `--model <slug>`. Если модель не настроена, daemon предоставляет только аутентифицированные средства настройки; Brain, каналы и cron запускаются после выбора модели. Все три клиента используют общие аккаунты и обновление токенов в одном `ANDA_HOME`. Учётные данные зашифрованы в `chatgpt/accounts.cose` и не записываются в config.yaml или хранилище браузера.

Перед переключением модели подписки дождитесь завершения задач и субагентов. Провайдеры подписки ChatGPT доступны только локальному владельцу: пока они включены, запросы других пользователей и внешних отправителей в мессенджерах отклоняются. Для аудио, видео и транскрипции нужны отдельные провайдеры. При достижении лимита автоматического переключения на платный ключ API не происходит. Используйте [настройки использования ChatGPT](https://chatgpt.com/settings/usage). Старые конфигурации `.codex/auth.json` сохраняют совместимость, но для новых подключений следует использовать этот способ входа.

На удалённом хосте или без браузера выполните `anda auth login chatgpt --no-browser --port 1455` и перенаправьте `127.0.0.1:1455` с компьютера браузера на хост daemon. Для переноса сессии выполните `anda auth export <profile-id> --output /absolute/path/session.json` (отключает исходный хост), передайте файл по SSH с правами `0600` и выполните `anda auth import /absolute/path/session.json` на целевом хосте. Импорт удаляет файл переноса и сохраняет идентификатор целевого хоста. Активируйте модель командой `anda auth use <profile-id> <model-slug>`. Не обновляйте одну и ту же сессию одновременно на двух хостах.
