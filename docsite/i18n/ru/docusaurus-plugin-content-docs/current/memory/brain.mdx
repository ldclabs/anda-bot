# Мозг памяти Brain

## Начните с одной беседы

Выполните `anda memory guide` для инструкции без сети. Обычной памяти не нужна отдельная настройка Brain или MIB. Сообщите устойчивое предпочтение, дождитесь обработки, откройте новую беседу через `/new` и спросите, что Anda помнит. Ответ «запомнил» не доказывает сохранение факта.

`anda memory` и `/memory` в TUI проверяют состояние без вызовов модели. Раздел **Память** показывает записи, проверенные источники и обработку бесед; граф доступен через исследование связей. Поиск может вызывать модель и не повторяется автоматически.

Проверьте предварительный просмотр перед исправлением, отключением или удалением. Отключение сохраняет записи в архиве, удаление очищает показанное нативное множество. Исключения источников переживают перезапуск, Notes обработки очищаются. Исходные чаты, файлы, журналы, копии и уже переданный контекст остаются. Неполные и неподдерживаемые области отклоняются. Исправление сначала спрашивает, какое это изменение: **Я ошибся** заменяет ваше прежнее утверждение, **Всё изменилось** записывает новое значение с этого момента, а старое остаётся верным для своего периода, **Ты записал неверно** просит Brain перечитать исходное сообщение и исправить запись. Удаление сообщает план стирания: завершено, частично, если какую-то поверхность не удалось проверить, или заблокировано юридическим удержанием.

В поле ввода можно выбрать режим новой беседы. CLI: `anda agent run --memory-mode no-store --prompt '…'` или `--memory-mode off`. Ограничивается автоматический доступ к Brain, но чаты и провайдеры не становятся анонимными. Подагенты, закладки и изменения cron тоже блокируются.

Для вопросов между беседами используйте настройку входящих или `anda memory inbox setup`. Проверьте и примените настройки, затем явно выполните `anda restart`. Пользовательские файлы и переменные окружения сохраняются. Подписка создаёт реальный вопрос при изменении записи. TUI: `/memory inbox`, `/memory answer <номер> <текст>`, `/memory retry <номер>`; повтор сохраняет событие и текст.

Читайте входящие командой `anda memory inbox`. Для следующей страницы выполните показанную команду `anda memory inbox --cursor <next_cursor>`. При `--json` курсор находится в `result.next_cursor`.

Сравнение MIB и бизнес-обучение — отдельные расширенные функции. Смотрите `anda memory evaluate plan --help` в сборке с MIB. Учёт стоимости может быть неполным. Сравнение памяти не одобряет бизнес-обучение и не доказывает общее улучшение.


Anda Brain — это система долгосрочной памяти, лежащая в основе Anda Bot. Это не обычная векторная база данных и не постоянно растущий Markdown-файл; это мозг памяти, созданный специально для AI-агентов.

Brain превращает разговоры, файлы, результаты работы инструментов и контекст каналов связи в растущую когнитивную сеть (Cognitive Nexus), объединяющую людей, проекты, предпочтения, события, решения, временные шкалы и взаимосвязи между ними.

## Трехфазный цикл

### Формирование (Formation)

Формирование кодирует полезные диалоги и результаты работы в структурированную память. Система не просто проверяет, появлялось ли конкретное предложение; она выясняет, кто это сказал, к какому проекту это относится, какие предпочтения раскрывает, какое решение было принято и когда это произошло.

### Вызов (Recall)

Вызов позволяет запрашивать данные из графа памяти с помощью естественного языка. Качественный вызов предоставляет необходимый контекст для текущей задачи, вместо того чтобы просто возвращать разрозненные похожие фрагменты текста.

### Обслуживание (Maintenance)

Обслуживание объединяет фрагменты информации, удаляет дублирующиеся данные, снижает влияние устаревших знаний и сохраняет хронологию изменений фактов.

## Как обучать Anda

Вам не нужно вручную редактировать файлы памяти. Намного эффективнее просто четко заявлять о стабильных фактах, изменениях и своих предпочтениях.

```text
Запомни: мне нравятся короткие описания релизов, но обязательно оставляй раздел с рисками.
Провайдер моделей по умолчанию для этого рабочего пространства изменился с A на B.
Когда мы упоминаем Алису, мы имеем в виду дизайнера команды мобильной разработки.
Помнишь ли ты предысторию проекта миграции платежей?
```

## Что делает память качественной

- Контекст: четко определены проект, человек, файл, канал связи или временной диапазон.
- Эволюция: при изменении предпочтений указывайте как старую, так и новую версию.
- Границы: временную информацию можно пометить как валидную только в рамках текущей задачи.
- Коррекция: если Anda запомнила что-то неверно, прямо укажите правильную версию.

## Локальные данные и провайдеры моделей

Данные графа памяти по умолчанию хранятся локально в директории `~/.anda/db`. Провайдеры моделей могут по-прежнему участвовать в процессах формирования памяти, поддержки вызова и обобщения, поэтому выбирайте провайдеров и точки подключения (endpoints) в соответствии с вашими требованиями к конфиденциальности.

Чтобы сделать провайдера предпочтительным для задач, связанных с памятью, добавьте метку `brain`:

```yaml
model:
  providers:
    - family: anthropic
      model: "deepseek-v4-pro"
      api_base: "https://api.deepseek.com/anthropic"
      api_key: "ВАШ_API_KEY"
      labels: ["primary", "brain"]
```

## Общая память с другими агентами

Claude Code, Codex и другие MCP-клиенты на той же машине могут пользоваться памятью Anda через MCP. Выдайте каждому агенту собственный токен; добавьте `--write`, чтобы агент мог также сообщать памяти, что запомнить:

```bash
anda memory agents add claude-code --write
```

Команда показывает токен один раз вместе с настройкой для Claude Code и Codex:

```bash
claude mcp add --transport http --scope user anda-memory http://127.0.0.1:8042/mcp/memory --header "Authorization: Bearer <token>"
```

```toml
# ~/.codex/config.toml; перед запуском Codex выполните export ANDA_MEMORY_TOKEN=<token>
[mcp_servers.anda-memory]
url = "http://127.0.0.1:8042/mcp/memory"
bearer_token_env_var = "ANDA_MEMORY_TOKEN"
```

Другие клиенты подключаются к той же конечной точке Streamable HTTP с заголовком `Authorization: Bearer <token>`. Она доступна по пути `/mcp/memory` на адресе daemon, принимает только loopback-имя хоста (`localhost`, `127.0.0.1` или `::1`) и отклоняет запросы с веб-страниц; каждый запрос всё равно требует токена, а клиент на другой машине подключается через туннель.

| Инструмент | Доступ | Что делает |
| --- | --- | --- |
| `recall_memory` | любой токен | Отвечает на вопрос по памяти с помощью модели памяти Anda; сначала недолго ждёт собственные заметки агента, которые ещё обрабатываются |
| `search_memory` | любой токен | Находит сущности по имени без вызова модели |
| `read_memory_entity` | любой токен | Перечисляет утверждения о сущности, от новых к старым, с текущей оценкой Anda и цитатами из источников, без вызова модели |
| `remember` | `--write` | Записывает заметку словами самого агента и передаёт её в Formation; `idempotency_key` делает повторную попытку безопасной |
| `memory_note_status` | `--write` | Сообщает, обработана ли заметка |

Заметка — это утверждение агента, приписанное ему как именованному участнику (например, «Claude Code»), но никогда не вам и не самой Anda. Она хранится в отдельном разговоре с источником `agent:claude-code`, а рабочая область **Память** показывает то, что Formation сформировала из неё, с этим источником — это можно исправить, перестать использовать или удалить, как любую другую запись.

Токен читает то же, что читает Anda, поэтому выдавайте его только агенту, которому доверяете свою память, и помните, что прочитанное им попадает к его поставщику моделей. Recall и Formation используют модели памяти Anda, и оплата идёт там. `anda memory agents` перечисляет выданные доступы и время последнего использования, а `anda memory agents revoke <id|client>` сразу отзывает токен. Токены действуют 90 дней, если `--days` не задаёт другой срок (до 3650). Anda хранит только дайджест каждого токена, поэтому потерянный токен нельзя показать снова: отзовите его и создайте новый. Пока Anda готовит обновление, конечная точка отвечает 503 до его завершения.

## Необязательная нативная среда

Укажите доверенный JSON/YAML в `brain.runtime_config` относительно каталога конфигурации; `BRAIN_RUNTIME_CONFIG` имеет приоритет. Перезапустите сервис для установки связей до загрузки Space. Входящие Brain в браузере и команды `/brain inbox`, `/brain status`, `/brain formation <id>` сохраняют подтверждённую личность. Чтение не разрешает выполнение; повторяйте ответ с тем же событием и текстом. Квитанция Recall подтверждает только доставку, принятие Formation не означает завершение. Функция `learning` независима от `mib`; семантика, utility, trust и автоматическое обучение требуют явной нативной конфигурации. Текущие IM-транспорты не являются автоматическими адаптерами действий. MIB persistent не заявляет обучение normal/ungated или полный учёт затрат. Каждое окно Formation — наблюдаемое намерение с долговременной квитанцией, поэтому прерванная отправка воспроизводит ту же квитанцию, а не обрабатывает окно дважды. `recall_memory` сначала недолго ждёт незавершённые окна своего разговора и сообщает, какие ещё обрабатываются. `brain_attention` также возвращает наступившие обязательства и сработавшие watch с момента последнего просмотра, а `brain_feedback` записывает собственный отчёт ассистента как атрибутированное свидетельство, а не оценку.

```yaml
brain:
  runtime_config: brain-runtime.yaml
```

Старые токены продолжают работать без повторного экспорта: запросы сохраняют исходную личность, а встроенный Brain принимает токен без audience, по-прежнему проверяя подпись и срок действия.
